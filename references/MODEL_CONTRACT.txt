Shared design model and adapter contract
=======================================

Purpose
-------
The library is an alternative way to work with DipTrace designs:
read a file, inspect or edit the design programmatically, then write a file,
with optional context. Each document family's supported serializations import
into the same model, using shared infrastructure across families.
Public ASC/DCHXML vocabulary guides names. The current design is the authority.
Import consumes one supplied design file. It does not discover companion files;
unavailable external resources remain explicit unresolved references.
Built-in imports identify both format and family from the supplied content:
native signatures, ASC Source declarations and XML root/type declarations.
Filenames and extensions do not select built-in input adapters. Explicit format
and family arguments remain caller overrides; headerless inspection fragments
need both. Output format selection follows the requested format or extension.
Custom file-reader registrations retain their documented explicit dispatch.
The generic entry point selects an available family adapter; that adapter owns
its contexts, model import, source inspection and output policy. Generic I/O must
not validate another family's context or use import metadata to select a writer.
One file read supplies the detected parser with the same buffer and source label.
Version queries and actual adapters use their family's same support declarations.

Named editing and consistency
-----------------------------
Schema-bound records expose named bracket/get/set access, presence and optional
deletion using Python mapping conventions. Schema definitions own type/default
and mutation rules. File positions are generated adapter views, not the required
public editing API. See ../doc/MODEL.md for concise access rules.

Resolved schematic electrical membership has one owner: each net's ordered pin identity
members. Pin.Net provides the reverse relationship and assignment operation;
NetNumber and component/pin member numbers are calculated. Preserve member order
when moving assignments and preserve identities when collections reorder.
Conflicting or unresolved imported occurrences remain investigable constraints;
do not guess a replacement. An edit that contradicts an existing wire attachment
fails before mutation. Coordinated connectivity editing remains a separate layer.

Named changes update affected properties, transitive property copies and bound
text through private dependency indexes. Validate the final proposed state before
changing values: reject incompatible types, ambiguous keys, dependency cycles and
mode changes that reinterpret existing resolved or unresolved identities.
Literal text remains independently authored.
Field-bound labels follow current source data. Family-specific selection rules
remain distinct; generic single-line refresh
keeps the first row identity and refuses to discard a referenced extra row.
User-field selections follow field identities when their collection reorders.
Text content refresh does not imply font, placement or routing recalculation.
RefDes collisions are an editing constraint, not a reason to reject imported
components. Preserve existing duplicate names and independent component identities.
Renaming rejects another component's equivalent occupied name across sheets and
hierarchy, atomically; unchanged assignments remain valid. Leading zeros in the
final counter do not create a new name. Legitimate multipart units remain one
component for coordinated naming purposes.
Calculated property users and guards declare their order, collection and
relationship dependencies. Bind, retarget and discard preflight a temporary
graph view; named property links can read calculated fields directly, including
fields with no positional argument or stored child. Committing a relationship
updates affected copies and private dependency indexes without duplicating the
calculated fact. First net assignment attaches its member and identity link only
after the combined tree/reference plan passes. A failed disconnection retains
the existing member and link. Cloning registers the complete copied topology
before evaluating calculated properties, independently of graph insertion order.
Domain-owned collection projections use the same prospective edit boundary:
prepare their rows and links before committing the controlling relationship.
Retain surviving row identities, reject removal of referenced rows, and leave
current data independent when its controller is released. Nested structural
previews compose with the enclosing tree/order proposal and restore it on exit.
validate() audits required fields, stored types, ownership and references without
projecting field values. It checks declared constraints without requiring callers
to read unresolved calculated getters. Writers also enforce destination requirements.
Advanced rebuild() additionally generates compatibility indices. Writers own
detached preparation; callers do not rebuild after ordinary supported edits.
Insertion, movement, reordering and removal preflight the affected reference
projections and schema constraints, then update them incrementally. Splitting a
referenced segment, reinterpreting an unresolved identity, violating a local
reference scope or removing referenced content fails before tree mutation.
Document.remove discards owned resolved/unresolved links collectively. External
users and unresolved scopes require explicit disposal or retargeting first.
Document.copy remaps internal targets and retains external targets for owned links;
incoming users remain on the original. Root field overrides must agree with copied
relationships. Projection fields crossing the selected subtree boundary require
explicit relationship editing. Named fields use assignment/deletion rather than
record lifecycle operations.
Subtree content clones do not implicitly acquire the original graph's links;
whole-document clones remap the graph to independent identities. New schematic
subtrees establish their schemas and recognized relationships through a combined
attachment plan. Forward identities remain unresolved; later target insertion
does not silently reinterpret them. Reference sources are selected from the new
subtree and its affected owners, without a whole-document binding pass. Mode
changes that introduce relationships use prospective values and scoped source
selection, including affected nested controllers and target constraints. Active
cache-prefix guards protect current member positions rather than count snapshots.
Internal adapter assembly and detached export preparation have
explicit boundaries for their incomplete intermediate structures.

Simulator expressions use named fields, including engineering suffixes and
expressions as text. Adapters generate positional arrays and counts. Additional
arguments with no established public name remain ordered typed Item records.
Compatibility vectors with unknown member meanings retain their typed order;
do not invent semantic flag names. Verification is a seven-boolean tuple.
Classification rows use one CategoryType kind across inputs. Declared catalog
keys are authored identities; occurrence indices such as pad-terminal Index are
calculated. PadTerminalCount derives from the current terminal list. Adapters
emit counts and destination row spellings without storing a duplicate fact.
Owned records/collections have separate immutable child definitions, including
declared cardinality and record type. Explicit validation checks those declared
constraints. A collection's serialized count is generated from its current rows;
it is not an additional editable scalar. The active cache prefix limit remains
a distinct stored setting and must not be confused with the link-array length.

read/parse and write/serialize use the same report and context contracts for
file/buffer operations. Reports collect attributed diagnostics, not clean-success
history. ExportContext owns common choices; destination additions remain explicit.
Construct defaults, inspect independent resolved choices and customize them with
dataclasses.replace. Configuration must not become stored design facts.

Import: modernization
---------------------
Readers decode their format and modernize supported earlier representations
into the current model. Verified version upgrades, equivalent aliases and
geometry modernization belong here. Verified DipTrace-style modernization is
the preferred default, implemented independently around our model. Match its
meaningful loading and normalization results. Each meaningful fact has one authoritative
representation. Old and current copies must not compete during later editing.

Preserve meaningful authored content, settings, identities, relationships and
ordering, including data another output format cannot express. A valid resolved
reference identifies its target; an unresolved reference explicitly retains the
missing key and relevant domain. Positional file indices are codec concerns.
Actual persistent identities remain normal design properties.

Unresolved-reference diagnostics default to warning. Expected unavailable
targets may be informational; that classification does not relax their edit
guards or invent a resolved target. Cloning and record copying retain it.

Import must not narrow a design to the capabilities of a future destination.
Modernization is distinct from destination adaptation.

Export: adaptation/projection
----------------------------
Writers adapt a detached view of the current design to the selected destination
and output version. They generate required counts, indices, obsolete compatible
representations and calculated values. Output must depend on current design
properties, destination/version and explicit context, without hidden dependence
on the original file or its edit history.

Context provides environment choices, overrides or services. Ordinary output
uses meaningful stored settings and documented defaults; no mandatory context
object should be needed just to supply routine choices.

Text layout and label appearance/measurement services belong to common.text.
Document adapters choose their own placement policies and compatibility views.
Full footprint text bounds use all lines and the authored angle; the older ASC
compatibility box is a separate projection. Environment font/DPI choices can
affect legacy automatic placement. Accept an explicit measurement service rather
than storing environment snapshots or adding design-specific placement rules.

Destination adaptation leaves the author's model unchanged. Expected regeneration
or equivalent normalization is quiet or informational. Meaningful irreversible
loss warns. Invalid output and unimplemented semantic mappings remain errors.

Missing and calculated data
---------------------------
Use ordinary nullable properties for unavailable optional data. Do not invent
an extra availability flag when presence already supplies that information.
An absent value and a known empty collection may differ when the domain requires
that distinction. Caches have clear ownership and invalidation; they are never
a second authoritative design value.

Generated component markings illustrate this rule: current component text and
label choices own content and placement. A MarkingGenerated drawing carries
appearance and optional calculated TextLine/Points_New caches. DCH and ASC output
recalculate those caches on a detached view; XML needs only the definitions.
Editing a value or placement does not require a refresh flag. Authored drawings
retain their geometry and appearance. Literal text uses FontType/TextShow zero;
a property or user-field selector instead binds its text to that current value.
Import and detached export preparation refresh bound text without replacing the
drawing. Editing its cached text cannot override the selected component property.

The unpublished PCB model applies this to copper pours: Poured=True with absent
Fill retains the filled choice without calculated geometry. A destination that
requires geometry for that choice exports it unfilled on a detached view.
Optional Fill/Regions separately owns calculated classification groups. Its
absence means unavailable classification; a present empty collection means no
assigned groups. Primitives reference group identities or None, with numerical
labels derived from the target Number. Unassigned members are valid within an
available classification. Neither representation invokes copper calculation.
See FORMAT_CAPABILITIES.txt for destination rules and diagnostics.

Numbers and source inspection
-----------------------------
Use appropriate discrete types for IDs, enums and flags, and one authoritative
real value per measured quantity. Prefer a single real-number representation;
binary64 is the initial simplification candidate. Exact parsing, integer codec
arithmetic and quantization can remain local to adapters where required.
Do not carry a second value to reproduce incidental source floating-point errors.
Conversion must preserve meaningful precision and must not accumulate drift.

Keep schematic angles as angles internally, including values outside a full turn.
Export normalizes modulo one turn and rounds to the nearest supported quarter
turn, encoding either a clean angle or an orientation number as required.
Half-way ties select an even quarter. Placement angles use degrees; text and
label angles use radians. Footprint pad/dimension and 3D angle domains are
separate and are not restricted by the schematic orientation rule.

Source spelling, comments, syntax trees, byte spans and transformation history
may support explicitly requested inspection or private research. Normal model
editing and serialization must not depend on them. Actual document properties
and authored library information are ordinary data, even when called metadata.
Document.representation describes the current schematic or syntax API view,
independently of diagnostic provenance. Normal imports all use schematic;
source inspection views normalize before semantic conversion. Clearing import
metadata cannot change reference binding, writer selection or output eligibility.
Import and export share ConversionReport and the info/warning/error severity
contract. Modernization/reconstruction is informational; unresolved constraints
or meaningful loss warn; invalid input/output fails with its original exception.
Reports describe operations without adding history to design properties.

Round trips and evidence
------------------------
For supported output versions, round trips should preserve meaningful design
data naturally because the model is complete and the adapters are correct.
A lost meaningful value identifies a missing model property or adapter mapping.
Fix that cause rather than adding source backups or preservation-only fields.
Required target fields with no independent meaning should be regenerated.

Byte equality is a useful diagnostic, not the architectural goal. Normalizing
an arbitrary file may change bytes just as an editor's own load/save can.
Keep connectivity, identity and version gates strict. Measure permitted layout
and rounding differences separately and verify stability through repeated cycles.
Observable design-file results from automated canonical conversions using
installed, licensed DipTrace software establish compatibility facts; they do not
prescribe our model or algorithms. This applies to fields, defaults, version
gates, normalization, connectivity, geometry and layout metrics alike.
Do not reproduce incidental bugs solely to pass comparisons.
Never imitate an apparent application rounding bug when our calculation is more
accurate or stable. Establish and document the numerical difference, preserve
meaning and verify repeated-conversion stability. Tiny application-induced
coordinate shifts do not require matching changes to authored geometry.
All model data, conversion rules and measurement tables use our own appropriate
representations. Their behavior must be observable and independently checkable
through design files and canonical conversions. Font profiles are one example:
character advances and line dimensions can be checked from exported layout.
Size calculation needs layout metrics, not glyph contours.
Independently establish the needed rules and measurements. Do not copy or
mechanically translate application code, runtime structures, table layouts or
explanatory text. Correct file-format constants and measurable numeric values
may agree; the implementation and representation remain our own.

Required cleanup
----------------
The following work belongs to completion of the schematic library:

- Classify existing StoredData and preservation mechanisms by actual meaning.
- Promote independently meaningful data to proper properties or references.
- Remove previous geometry, removed-point histories and other upgrade snapshots
  from ordinary model data after their verified modernization is implemented.
- Regenerate obsolete label slots and redundant compatibility representations.
- Replace duplicate numeric truth/calculation values with a simpler numeric path.
- Express inherited style choices clearly, with optional resolved caches only
  when useful and with explicit invalidation.
- Consolidate unresolved-reference state instead of scattering saved keys and
  positional placeholders through preservation metadata.
- Remove ordinary editing/export behavior that varies solely with import origin.
- Keep optional source inspection separate from normal library workflows.
- Revise tests, diagnostics and capability documentation to enforce this contract.

Cleanup must not blindly delete meaningful data. Determine its role from public
format semantics and verified behavior, retaining research evidence privately.
The capability register must distinguish present behavior, cleanup work and
actual destination limits; existing retention behavior is not a model precedent.

Shared XML output infrastructure
-------------------------------
Typed XML values, physical pad styles/terminals, font compatibility fields,
physical drawing/dimension data, 3D placement, catalogues and key allocation are
shared where their meanings agree. Family adapters own version decisions,
placement semantics and identity-to-output-key projection. Keys are allocated
on the detached output view, reserving declared and unresolved keys before new
ones; allocation never adds serializer bookkeeping to the current model.
Each nested library header owns its import units and compatibility conventions.
Sheet title grids, styled content and column-major table layout also share their
records and XML helpers. Document adapters choose placement and font/version
conventions; shared helpers do not impose one family's rules on another.
