Editable schematic document library

Supporting implementation/API notes. Start with ../doc/GETTING_STARTED.md for
ordinary use, ../doc/API.md for supported operations and ../doc/MODEL.md for
design meaning. The single generated field catalogue is ../doc/SCHEMATIC.md.

DCH, ASC and DCHXML import into the same ordered Element/Value model. Field names
follow the public ASC and DCHXML vocabulary. The library is independent of an
installed application and does not use retained input bytes to reconstruct DCH.

The model represents the current design. Modernization belongs to import;
adaptation/projection belongs to export. See MODEL_CONTRACT.txt for the agreed
architecture. Remaining adapter limits are recorded in FORMAT_CAPABILITIES.txt.

Supported boundaries

DCH input: schemas 29 through 52. Unknown versions are rejected.
DCH output: schemas 46 through 52. System-font measurement services can require
explicit environment inputs.
ASC: schematic dialect 46. AscExportContext supplies optional overrides.
DCHXML: recognized public schematic fields, with 4.3, 4.9, 5.2 and 5.3 output vocabulary.
DchXmlExportContext supplies optional overrides.

Select version=52 for fractional sizes, monospaced vector fonts and the current
XML vocabulary. The default output target remains 46. FontSize, NameFontSize,
MarkingFontSize and the global font settings each own one numeric size; the
adapters generate integral compatibility fields when necessary. FontMono,
NameFontMono, DefFontMono and Settings.PartFontMono select monospacing.
Settings.NetNameFontSize owns the global net-label size. Advanced simulator
settings use the public OptionsGeneral/OptionsDC/OptionsAC/OptionsTransient
groups under ssimulator, with sim_digital for the four digital arguments.
Argument groups expose named text fields, for example sim_ac.StartFrequency and
sim_digital.GroupBuses. Counts and positional pt rows are generated by adapters.

Import consumes one supplied design file; it does not discover companion designs
or picture files. Old picture references may remain unresolved BitmapIndex values.
Picture_File and an optional variable expression supply a current path. An explicit
legacy_picture_files export context can also resolve the reference without reading
another design. ASC retains an unresolved index with a receiver-compatibility
warning. DCHXML and current DCH output keep the picture geometry with an unassigned
source and a loss warning. The authoring reference remains intact.

Export contexts can explicitly refresh global user-field choices with
refresh_user_fields=True. This builds the list from enabled components while
preserving matching display choices. Default export preserves the stored list.
ASC exports compact inactive records by default and report inactive-records
warnings. AscExportContext(compact_inactive=False) retains representable inactive
content. This choice is independent of the imported format. Modern label choices
are authoritative; writers regenerate obsolete label slots. legacy_text_slots
supplies an explicit initial compatibility-output context when desired.
Generated label text and anchors are calculated caches. DCH and ASC writers
rebuild them from current component values and ShowRefDes/ShowName/ShowValue,
other label choices and UserFields. No manual refresh is required. The cached
Points_New and TextLine containers may be absent. Generated drawing appearance
remains editable; change the label choice to move a generated label, or set
MarkingGenerated=False to retain authored placement and appearance. FontType
(XML TextShow) still selects the text source: zero is literal text; component
property and user-field kinds refresh from their current values on import and
export. For independent literal text, remove any user-field identity binding
before setting FontType=0. No refresh flag is required after editing a bound value.
User-field label drawings bind to their UserField identities. Reordering fields
keeps each drawing's appearance with its field; FontType is rebuilt from that
relationship. Retarget the marking-user-field reference to change its owner.
XML carries label definitions and does not require calculated drawing caches.
It warns when individual generated-label drawing attributes
differ from what those definitions and global settings reconstruct.
New labels use the stored marking font family, or a single common family already
on active generated labels. Mixed families remain individual choices. An empty
system family uses the receiving environment; optional context selects a
reproducible family. XML keeps the global family; individual families omitted by
its current global mapping warn. DCH/ASC warn when generated labels cannot carry
an unambiguous global choice. Export leaves the authoring model unchanged.
Owned footprints are exported even with an empty name. Names remain editable
text; complete definition content determines XML style sharing.
Default DCH output retains inactive records; compact_inactive=True requests
compaction explicitly. ASC compaction remains enabled by default.
Placed footprint compaction includes unused pads/drawings and disabled
holes/dimensions; boundary records remain. Cached definitions are independent.

read(path) and parse(data, format='dch'/'asc'/'dchxml') produce the same shared
schematic model. parse accepts byte buffers; ASC and XML also accept text.
read_source(path), parse_source(data, format=...) and the low-level
format-specific parsers provide optional syntax-level inspection. Unsupported
semantic data raises an explicit error rather than returning another model.
Document.representation identifies the current API view: schematic for every
normal import, asc/dchxml for their source views, and tree for a generic ordered
tree. It is independent of diagnostic metadata and survives cloning. Clearing
provenance does not affect reference binding, normalization or writer selection.
Source views require as_schematic() before semantic conversion. For programmatic
construction, new_schematic() supplies the common model and declared defaults.

Older DCH input modernizes labels, selection sizes and origins during reading.
read(..., context=ImportContext(...)) and parse(..., context=...) accept optional
import defaults and a TextLayout service. Stored font settings win over defaults.
Vector placement is self-contained. System-font placement uses a supplied service
or a lazy Windows measurement backend; other platforms must supply that service
when a legacy placement needs it. Reading does not launch an application or GUI.
The Windows backend calls GDI directly through ctypes. Vector size calculation
uses an independent table of measurable character advances and line dimensions,
without glyph outlines or an external font engine.
Properties absent from older layouts, including supplier strings, variable paths
and ProjectDir, receive declared current defaults during import and can be edited
immediately. Optional environment-dependent supplier preference stays absent
until a destination requires its default.
All imports give blank enabled-instance user-field names their standard Untitled
name and remove final ASCII-space-only rows from table/title cell text. Ordinary
text, interior blank cell rows and nonblank row spacing remain meaningful.
All three imports apply established route normalization by geometry and attachment
state, independently of input version. Referenced identities remain intact;
unresolved attachment domains defer changes with a warning. Short branches can
gain bends, project onto their host or move a corner join onto an adjacent host
segment. Pins stay fixed; dependent short branches follow settled host geometry
independently of array order. Consistent routes need no reconstruction. A general
routing engine and longer/cyclic repair constraints remain outside this scope.

Data and editing

Document owns an ordered tree. Element has a stable identity, parent, ordered
children and change tracking. Immutable Value records hold typed data, optional
units and optional diagnostic provenance. Each current fact has one authoritative
value. Complete imports contain current properties and references. Decoding older
drawings uses temporary typed inputs that are removed after modernization;
they are not source backups in the editable design. Earlier occurrences are not
an architectural requirement for natural round trips.
Public pad keys are editable Pad.Id properties. Missing local references share
UnresolvedKeys/Key(field_name, missing_key), with scoped graph guards preventing
accidental rebinding after structural edits. XML retains those keys; positional
exports use unassigned references on a detached view and report warnings.

Shared lengths use three units per millimetre, .0762 per mil and 76.2 per inch.
XML adapts physical units and reverses two-dimensional Y. Component Angle is in
degrees; pad and drawing angles use their documented field conventions.
Each quantity has one current numeric value. Decimal unit conversion retains
decimal precision without a separate source-biased calculation value. Binary output applies
each field's required quantization; repeated conversions should not add drift.
PadAngle is authoritative; legacy Inverted flags are generated by the adapters.
Pad.Standard is independent of that angle. DCH keeps both current values; ASC
projects its angle-dependent Standard value, and XML uses the relationship
between default and selected pad styles. These calculated adaptations report
information when needed and leave the authoring model intact.
Footprint drawing Width is the current pen setting. Negative widths request an
inherited pen: ASC resolves it with line_width(layer) or the standard 0.1 shared
units. Earlier ASC header widths are replaced by the named setting on import;
they do not override later exports or depend on whether a field has been edited.
Each DisableTopMask/DisableBottomMask/DisableTopPaste/DisableBottomPaste property
holds one integer mode, rather than an old boolean/state tuple. See the capability
register for the mask and paste mode names and compatibility projections.

  from lib import read

  document = read('input.dch')
  part = document.one('/Schematic/Components/Part[RefDes="R1"]')
  part['Value'] = '22k'
  print(part.inspect())
  part.move_to(part.parent, 0)
  document.save_dch('output.dch', version=46)

Selectors support child paths, descendants (//), wildcards, one-based ordinals,
child-scalar equality and zero-based argument predicates. Boolean predicates
are distinct from numeric values. Matching quotes inside quoted predicates can
be doubled; backslashes remain literal. Examples:

  //Part[Value="100n"]
  //Part[Locked=true]
  /Schematic/Components/Part[2]
  //Part[RefDes="C10"]

Argument predicates (@N) and raw set_field/scalar access remain available to
adapters and source inspection. Ordinary editing uses named bracket/get/set
access, which also maintains relationships and derived values.

The selector / identifies the tree root. Each element's current path resolves
back to that element, including after a move or reorder.

Document and Element select(path, where=predicate) and one(path, where=predicate)
apply an optional callable to final path matches, preserving their order.
one() checks cardinality after filtering. find_all() uses the same where contract.
Predicates can combine ordinary Python numeric, string and boolean comparisons.
They use the supplied data fields; no geometric containment is inferred.

Document.refdes(prefix) returns a live RefDesFamily of enabled physical components
(PartType=0) across all sheets. Matching excludes cache definitions and logical
symbols. matches(reference=None) returns all records in counter/spelling order,
including multipart occurrences; designators() returns distinct literal names.
Family membership and matches(reference) compare the exact prefix and final
ASCII numeric counter. R003 and R3 are equivalent; R1-X2 has prefix R1-X, not R1-.
A missing suffix is zero: a bare prefix and its explicit zero suffix are equal.
R-1 has prefix R- and counter 1. Underscores, dashes and % are literal prefix
characters. Ordinary spaces are rejected for authoring/helper inputs; the editor
removes them during renaming. This is not a format-load rejection or rewrite.
Prefixes retain case and cannot end in ASCII digits. Existing names retain
spelling, while generated names use unpadded decimal digits.

first()/last() return the numeric endpoints or None. first_free(start=1) suggests
an unused name at or above start and reserves nothing. next(reference, mode=...)
and previous(reference, mode=...) require number, existing or free. They search
strictly beyond the supplied number. The lower counter bound is zero; unavailable
backward/occupied results return None. Numeric and free modes generate names;
existing mode returns the stored spelling. Matching is distinct from exact-text
selector equality. split_refdes(name) exposes the shared (prefix, integer) key.
Empty/unassigned names raise ValueError there and are omitted from families.
Other incompatible stored names make family operations raise rather than silently
assuming that their counters are available. Source data remains unchanged.

RefDesFamily(prefix, references, get_refdes=None) also accepts standalone string
iterables (captured once) or a callable supplying current items. get_refdes
selects the text when those items are records. A document view supplies current
components, so append/remove/rename/enable edits need no explicit refresh.
Named physical-component RefDes edits reject occupied targets atomically.
Attachments preserve existing literal multipart names but reject competing
spellings of the same counter. Independently stored multipart names require
coordinated edits; these helpers do not introduce group renaming or reservations.

References bind identities and keep affected indices/keys current while editing.
They cover component and pin membership, wire segments, buses, pages, groups,
cache links, local pad links, dimensions, hierarchy and simulator identities.
References expose targets and current projected values. Existing unresolved values
remain inspectable; ambiguous targets or incompatible edits raise ReferenceError.
Use references.retarget() for managed links instead of editing their indices.
Element.clone() copies a subtree; Document.clone() also copies its reference graph.
Document.copy(record, parent=..., fields={...}) copies owned links, remaps internal
targets and retains external targets. Incoming users stay on the original.
Document.remove(record) discards owned links atomically, preserving external users
and unresolved scopes. Cross-boundary projection fields require explicit editing.
validate() audits declared fields, ownership and references without changing data.
Advanced rebuild() additionally projects compatibility fields; normal saves do
not require it.
New unresolved links guard the collection state at registration. Existing issues
continue to guard their earlier state, including changes that failed validation.
The guard also prevents renumbering that would give a missing key an unrelated
target. Resolve or clear that link before canonicalizing its target numbering;
noncolliding numbering and unrelated collections can still be rebuilt. Validation
precedes changes to the projected values.

Export choices and diagnostics

  document.save_asc('output.asc')
  document.save_dchxml('output.dchxml')

Export context is optional. Stored document choices take precedence over standard
defaults: mm, vector text, font size 2, grid snap enabled and fallback line width
0.1 in shared length units. Explicit context values override those choices only
in the exported view. ASC units select display units; XML units also determine
serialized physical lengths. The author's model remains unchanged.

  from lib import AscExportContext, DchXmlExportContext, ExportReport
  from lib.schematic.layout.markings import MarkingStyle

  style = MarkingStyle(vector=True, font_size=2)
  asc_context = AscExportContext(units='mm', project_dir='', grid_snap=True,
                                 marking_style=style, line_width=lambda layer: .2)
  report = ExportReport()
  document.save_asc('output.asc', context=asc_context, report=report)
  for notice in report.notices:
      print(notice.severity, notice.rule, notice.message, notice.paths)

  xml_context = DchXmlExportContext(units='mm')
  document.save_dchxml('output.dchxml', context=xml_context, version=46)

System-font layout uses an injected measurement service or a lazy Windows font
backend. Other platforms must supply a service when system-font calculation is
needed. Vector layout is self-contained. PathVariables supplies explicit project, installation and custom
path aliases. Contexts keep environment choices separate from imported facts.
For old inputs without a saved MainSupplier match flag, DCH and ASC use False.
AscExportContext(default_main_supplier=True) changes that fallback; existing
saved flags always take precedence. The choice is an informational export notice.

ASC input and output default to Windows-1252. A UTF-8 BOM identifies that input
encoding; otherwise use read(..., encoding='utf-8') or the corresponding parse
option for UTF-8 bytes. Shared imports do not choose future export encodings.
AscExportContext(encoding='utf-8') selects Unicode text; the encoding argument
of to_asc_bytes overrides the context before text projection. The ASC dialect
does not declare its codepage, so choose the receiving application's encoding.
Windows-1252 substitutions warn; other explicit encodings require representable text.
Some ASC reader fields also change literal ! to spaces. A scoped compatibility
warning reports this behavior while preserving the punctuation in the file and
model; this library's own ASC reader retains it. See FORMAT_CAPABILITIES.txt.

ConversionReport works with read(), parse(), parse_dch(), source-view readers
and as_schematic(), and with every export. ImportReport and ExportReport are
compatible aliases for that same type. One report can cover a whole conversion:

  from lib import ConversionReport, read
  report = ConversionReport()
  design = read('design.dch', report=report)
  design.save_dchxml('design.dchxml', report=report)

report.notices collects ordered info, warning and error diagnostics; infos,
warnings and errors return filtered lists. Each notice includes operation
('import' or 'export'), format, severity, rule, message, paths and recoverability.
destination remains a compatible spelling of format. Routine modernization and
reconstruction are quiet by default. Unresolved identities, deferred repairs and
meaningful irreversible omissions emit ConversionWarning unless a report is
supplied. Errors are collected before their original exception is raised; a
report never allows invalid input or output to continue. Reuse appends notices;
clear() resets the same report in place for another operation or batch. Filtered
infos/warnings/errors lists already retrieved by a caller remain snapshots.
Import reports are
sidecar diagnostics, without modernization history in design properties.
Legacy document.diagnostics and references.issues remain available. Exact byte
differences alone do not imply a warning. See FORMAT_CAPABILITIES.txt.

All export compatibility changes occur on a detached view. XML-only metadata,
standalone resources and unusual source states stay in the author's model.
Same-format output retains modeled facts subject to the selected output version.
Byte identity also depends on output schema, numeric representation and explicit
environment choices; it is not promised for every cross-format cycle.

XML import modernizes discrete placement into the current angle and geometry;
nonterminating placement states produce a bounded input error. Schematic angles
can be edited beyond a full turn. All writers normalize and round them to the
nearest quarter turn (half-way ties to an even quarter), leaving the model intact.
This rule does not restrict footprint pad/dimension or 3D angles.
Unrecognized XML labels/fields and missing required styles or resources need an
explicit mapping. Missing local object/group keys remain typed unresolved data.
Known dimensions bind pad, shape, hole, terminal and polygon-point identities.
Unresolved selectors remain searchable as literal facts; related structural
changes need an explicit mapping, while unrelated collections remain editable.
See FORMAT_CAPABILITIES.txt for the representation and export rules.

Data editing is the current scope. Coordinated wiring operations, trace following,
routing and copper-pour recalculation belong to later layers.

Format/version support
----------------------
from lib import format_capabilities
capabilities = format_capabilities('dch')  # Leading dots and case are normalized.

FormatCapabilities is immutable. It exposes format, family, read_versions,
write_versions and default_write_version. supports_read(version) and
supports_write(version) test exact adapter support. DCH and ASC versions are
integer schemas/dialects; DCHXML read_versions lists recognized major.minor XML
dialects, while its write_versions uses target schematic schema numbers.

output_version() returns the default. output_version(requested) requires an
exact writable version. With fallback=True, an unsupported integer target may
select the greatest supported earlier version; it never selects a newer one.
Callers must report a fallback when the returned version differs from the
request. If no earlier version exists, it still raises ValueError. A capability
query does not project a design or predict its design-specific conversion loss;
ConversionReport remains responsible for that information.

Schematic revision declarations in lib/schematic/formats/capabilities.py are the
source of truth for the query, binary header acceptance, DCH writer gates,
DCH/XML defaults and XML application-version selection. Feature
mappings remain with the adapters. Extend the declarations after implementing
and verifying the corresponding mappings; portable tests exercise every declared
output version through writing and re-import.
