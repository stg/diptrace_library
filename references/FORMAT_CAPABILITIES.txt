Format capabilities and conversion diagnostics
==============================================

Contract
--------

DCH, ASC and DCHXML import into one searchable, editable model. Every supported
meaningful design fact has one authoritative representation. Modernization is
part of import; adaptation/projection is part of export. See MODEL_CONTRACT.txt
for the agreed architecture and required model cleanup.

Document.representation identifies the current schematic or syntax API view;
it is not import history. All normal inputs use schematic. Provenance metadata
may be cleared without changing reference binding or export eligibility. Source
inspection views normalize through as_schematic() before semantic conversion;
incomplete documents remain ineligible for complete output.

Import modernizes supported older representations into the current design.
Verified DipTrace-style modernization is the preferred default import behavior.
Unavailable optional/calculated data uses absent values without extra availability
flags. Destination compatibility changes occur on detached export views. Diagnostics
distinguish routine normalization, reconstructible data and meaningful loss.
A destination omission does not remove facts from the authoring model.

Implementation status: entries below record current adapter behavior. Complete
imports contain current properties and references, without historical snapshots
or preservation-only StoredData. Older drawing codecs use temporary inputs during
modernization. The agreed model contract takes precedence. Same-version preservation follows from a complete model
and correct adapters, without source replay or historical backups.

Severity   Meaning                                      Default behavior
info       Equivalent normalization or reconstruction   Quiet; collect if wanted
warning    Meaningful loss, unresolved or deferred data ConversionWarning
error      Unsupported mapping or invalid input/output  Raise original exception

ConversionReport.notices preserves order across severities and operations.
ImportReport and ExportReport alias the same type. Its infos, warnings and errors
views filter those notices. operation identifies import/export; format identifies
the input/output dialect (destination is a compatible spelling). read(), parse(),
parse_dch(), read_source(), parse_source() and as_schematic() accept report=.
A supplied report suppresses automatic Python warnings, but errors still raise.
Import failures, including file I/O, use import-failed; export failures, including
file I/O, use export-failed. The original exception type/message remains available.
Caller report-type errors remain ordinary TypeError. Reusing a report preserves
notices from each operation; clear() empties the collector in place. Reports do not add source snapshots or duplicate facts
to the authoring model. Existing diagnostics/reference issues remain inspectable.
Notices also expose file (a supplied input/output path, otherwise None) and an
optional caller label. Labels attribute buffer operations without treating their
contents as filenames. Reports collect diagnostics, not clean-success history.

Named editing and relationship views
------------------------------------
Schema-bound records support named bracket/get/set access, presence checks and
optional deletion; see ../doc/MODEL.md for the concise access rules.
Label tuples expose public Show/ShowPart/Align/Horz/Vert/X/Y/Angle members.
User fields expose Name/Value/Type and component label members. Table/title
bounds, borders, size rows, drawing points and text rows have named storage;
their file tuples are generated views. Grid Column/Row, title-block Position,
and pin/pad/title-field occurrence indices are calculated from current order.
Self-index bindings are unnecessary when that index is already calculated.
Authored table-cell bounds remain independent geometric data.
Footprint holes expose Enabled/Locked/X/Y/Diam/HoleDiam/Group. Library slot and
variant Index values derive from current order; LibPath is an authored slot field.
Simulator argument groups use public named fields, with expressions retained as
text. DCH and XML readers populate them directly; ASC rows normalize on import.
Writers generate positional arguments/counts, preserving additional ordered Item
arguments. Cached Verification is a typed seven-boolean compatibility tuple;
individual check meanings are not claimed.
Named edits propagate through dependent property/key copies and bound text.
Prospective validation checks the final values, types, unique keys and guards
before mutation. Guards also protect unresolved identities against mode changes.
Attaching records and assigning unused relationship fields activate recognized
links through targeted prospective plans. Controller changes include affected
nested sources and target-type constraints. Bound text also follows property
copy chains, binding and retargeting; conflicting copies and calculation cycles
fail before mutation. Label text is calculated while its FontType selects a
component field; switch to literal mode before authoring independent text.
Document.copy copies owned resolved/unresolved relationships, remapping internal
targets and retaining external targets. Incoming users stay on the original.
Root field overrides cannot disagree with managed values. Document.remove
discards owned links atomically; external dependencies and unresolved scopes
remain protected. Relationships whose projection fields cross the chosen subtree
boundary require explicit editing. Field assignment/deletion uses named access.
Wire/bus rows and point X/Y/Dir, classification rows and declared catalog keys,
project paths, model text lines, global user-label choices, differential pairs,
internal pad links, paste segments and pad terminals have named definitions.
Classification input spellings normalize to CategoryType in the common model.
Adapters generate their destination names. PadTerminalCount and terminal Index
derive from the current list, including after insertion/removal/reordering;
constructors and direct readers do not retain an independent count.
Page HorzZoneBorder/VertZoneBorder are fractional lengths in shared units.
Drawing definitions distinguish SymbolDrawing, SheetDrawing and PatternDrawing.
Their fields follow their current ownership context. Obsolete label, component
orientation and pad compatibility slots are excluded from editable definitions;
adapters generate them from current properties. GridSnap and MarkingFontName
are optional settings. XML library additions such as cached-symbol Datasheet,
cached-pin SignalDelay and footprint Datasheet/RefDes/Sided also have optional
named definitions; existing destination omission diagnostics still apply.
../doc/SCHEMATIC.md is generated from the same immutable definitions returned by
schematic_schema(). It covers the supported record types, fields, tuple members
and owned collections. Unknown enum meanings and units are left unspecified.
Declared child records and collections have immutable ownership/cardinality
metadata, checked by validate(). Empty collections require child() navigation.
Classification arrays, possible-name lists, paste segments, project path lists
and cache-link arrays no longer store their serialized row counts in the normal
model. ASC/DCH output generates those counts. DesignCache_Count retains its
different meaning as the last active cache-link position. Active cache links
expose named, reference-managed SlotIndex values; inactive capacity entries
remain typed literal values.
Expanding the active prefix registers additional recognized links. Guards use
current entry positions, not a historical count snapshot. Shrinking or moving an
active entry beyond the limit requires explicit relationship disposal first;
otherwise the edit fails atomically. Unresolved entries retain their scopes.
For agreeing resolved pin/net occurrences, ordered Net.Parts members own the
pin identity. Pin.Net is the derived/editable reverse view; NetNumber and member
indices are calculated compatibility values. No duplicate numeric membership
is stored. Ambiguous, contradictory or missing imported identities are not
consolidated or guessed. Wire attachments constrain membership edits; coordinated
connection editing is deferred. All three adapters consume the same relationship.

ExportContext provides shared overrides; DchExportContext, AscExportContext and
DchXmlExportContext define destination additions. Explicit unsupported options
raise rather than being ignored. Context.resolved(document) returns independent
effective choices; a common context accepts format= to resolve for a destination
before customization. DCH no longer requires an ASC-named configuration and honors
explicit unit-display and part-font-color overrides on its detached view.
DCH does not serialize GridSnap; an explicit grid_snap output override is rejected.
ASC unit overrides affect both its header and settings; the header alone does not
override stored unit settings or rescale coordinates on import.
serialize() is the bytes-output counterpart to parse(), sharing write() options.
validate() audits declared stored values, required fields, ownership and references
without rewriting values; advanced rebuild() also projects
compatibility indices. Neither operation invents missing identities.

Preserving the source model is not the same as recovering facts from a converted
file. Recoverability descriptions must distinguish these two. Successful reimport
alone does not establish semantic or binary equivalence. An adapter limitation
does not establish an inherent format limitation.

Calculated markings can be generated from definitions and context. Their
reconstruction is routine, not meaningful loss. Numeric quantization and bounded
text-layout differences are likewise diagnostic unless they change meaning or
accumulate drift. No notice is needed for every regenerated point or rounded
number. Arbitrary original compatibility values may be unrecoverable without
affecting meaning; byte identity alone does not set severity.
An apparent application rounding bug must not be imitated when our calculation
is more accurate or stable. Record measured deviations and check meaning and
repeated-conversion stability; retain authored coordinates rather than introducing
an incidental tiny shift solely for exact comparison.

RECENT_SCHEMATIC_REVISIONS
Font sizes remain single numeric model properties, including FontSize,
NameFontSize, MarkingFontSize, DefFontSize, ZoneFontSize and the global settings.
Import replaces an older integral compatibility occurrence with its later
fractional value. XML FontSizeFloat/MarkingFontSizeFloat are syntax for those
same properties, not additional authoring facts. Writers derive compatibility
integers using nearest-even rounding; there is no historical integer backup.
DCH below 52 and earlier XML vocabulary round fractional sizes with warning
fractional-font-size. ASC dialect 46 can carry fractional values directly.

Monospacing uses FontMono on drawings, dimensions, cells and title contents;
NameFontMono on pins; DefFontMono on tables; Settings.PartFontMono globally.
Older inputs use false. DCH/XML schema 52 carry these choices. ASC and earlier
destinations omit them with warning monospaced-font when selected. The built-in
layout service supports monospaced vector advances; system-font measurement
retains fractional sizes until the backend's point-size quantization.

Settings.NetNameFontSize defaults to 4 for older input. DCH/XML targets >=49
carry it. Earlier targets and ASC omit a nondefault value with warning
net-name-font. Fractional net-name sizes require DCH/XML >=52.

Simulator options use the public OptionsGeneral, OptionsDC, OptionsAC and
OptionsTransient groups under ssimulator. Engineering values/expressions remain
strings; switches and iteration choices are booleans/integers. sim_digital holds
StartTime, Step, StopTime and GroupBuses arguments; tp=10 selects digital mode.
DCH/XML targets >=50 carry these settings. Older targets and ASC omit nondefault
options with warning simulator-options. DCH/XML targets below 50 disable digital
mode with warning digital-simulation. ASC retains the numeric mode but omits its
digital argument array. XML 5.2 uses the numeric mode label; 5.3 names it Digital.
The 5.2 XML reader resets digital arguments even on its own exported files.
Targets 50/51 retain these arguments in the XML (the fourth uses Item) and warn
dchxml-reader-digital-arguments for nondefault values. Our reader preserves
them; use the 5.3 dialect for application readback that also preserves them.
This is a receiving-reader limitation, not a restriction of XML data storage.

PictureFlipped defaults to false and applies to sheet pictures. DCH >=51 stores
the drawing flag; XML >=52 exports it on Picture drawings. The 5.2 XML dialect
omits it despite supporting binary schema 51. ASC and earlier XML/DCH targets
omit a selected flag with warning picture-flipped. The source
model is unaffected by all these export adaptations.

XML targets 49..51 use the verified 5.2 dialect with the selected feature subset;
this does not claim those schemas first appeared in that application release.
Target 52 uses 5.3 vocabulary. Embedded footprint definitions precede component
definitions so readers can resolve references in one pass. Definition-local
enumeration Id attributes are optional bookkeeping, without additional model
identities; style keys and ordered records establish schematic associations.
XML 5.3 Pad.DefStyle maps to the existing pad Standard property. Earlier XML
infers it from default-style selection. The newer vocabulary can therefore share
equal pad geometry while retaining independent default-style choices.
Mounting=None and dimension Connected=None map to the existing unassigned -1.
Optional XML TextWidth/TextHeight are calculated extents; imports use editable
font, text and anchor facts and do not retain redundant historical measurements.
Newer placed BaseName, Manufacturer, Datasheet and PartString fields map directly
to existing component properties.

Measured monospaced vector boxes agree within 0.0001 shared length unit for the
tested ordinary text, markup and single-code-unit characters at sizes 2..10.
Unsupported supplementary glyph fallback can differ by up to 0.102 shared unit
(0.034 mm) over that range. This concerns calculated bounds, not stored text,
font sizes or anchors, and does not accumulate into authoring coordinates.
The proportional-font layout profile retains its established metrics; exact
matching of every application/font engine's calculated text bounds is not claimed.

DOCUMENT_AND_PAGE_SETTINGS
The actual input signature/version remain diagnostic document metadata. The
nominal Source identification record does not select the output format/version.
Root Scale (percent), Xpos and Ypos have named fields; Scale and page scale keep the loaded, bounded values;
earlier scale values and integer viewport occurrences are discarded. Writers
derive compatibility integers and repeated layout counts from current values.
Document and per-page viewports are independent settings. XML stores per-page
views; import initializes the root viewport from its selected page. XML export
uses the current per-page views. It does not preserve a separate root viewport.
Optional Schematic.ActiveSheet stores XML's selected page as a maintained index
link; reordering pages preserves the selected identity. XML output uses that
selection, then first-page fallback when absent, with an optional context override.
Current DCH/ASC adapters omit selection and report a nondefault selection as info;
page content and per-page view settings remain in the authoring design and output.
Settings.UnitsMM, UnitsMIL and UnitsINCH own the current display-unit choices.
ASC's earlier Units header does not override them or rescale physical geometry
during import. XML physical units are converted into shared lengths and these
current settings, without a shadow unit selection in metadata. Later edits to
the settings control default exports from every input format. Optional context
can select another output view; XML converts lengths while ASC keeps shared
physical coordinates and writes the selected header.
Page.FontLineWidth is an ordinary editable zone-font property, mapped directly
to DCH and DCHXML. ASC has no corresponding field and supplies its default on import.
Page.PageType owns the current page kind. DCH consumes and discards its earlier
compatibility occurrence, then writes the current property in both required
positions. No previous PageType value is retained in the model.
Settings.GridSize is the sole current grid spacing. DCH import resolves the
serialized numerator/divisor and discards that redundant pair. The writer derives
a bounded denominator to retain small-grid precision, then quantizes its numerator.
Unedited and edited grids follow the same output calculation.
Grid division uses an independent Decimal context, so the caller's precision or
rounding settings do not change the imported spacing. Repeating a binary save
stabilizes the same serialized ratio; no earlier rounded value is retained.
Older inputs also receive current supplier fields, variable-path properties and
ProjectDir during import, using declared defaults where no value was stored.
These properties are searchable and editable before any export. An absent
MainSupplier preference remains optional; DCH/ASC output supplies the configured
default only when that current property is absent. Source-version annotations
do not select supplier defaults.
The earlier DCH companion-picture count never introduces inline strings. It is
consumed and discarded; current output writes zero. For pre-42 input with a
nonzero count, a diagnostic identifies unavailable picture filenames. Import
consumes one supplied design file. Companion discovery is outside this boundary;
an unresolved picture key remains ordinary editable reference data. ProjectLibs
properties describe separate library preferences and are unrelated to this count.

ASC_LABEL_SLOTS
Modern imports discard obsolete global and instance label slots once modern
choices are available. Writers generate compatibility slots from those choices;
ASC's optional legacy_text_slots context can supply an explicit initial output
state. Import origin does not select a preservation policy. Independent historical
slots are not design facts in the current
model. Pre-40 inputs modernize font-dependent label anchors during import, before
selection-size and origin migration. ImportContext supplies optional environment
inputs; vector placement is self-contained, and system-font placement uses a
provided TextLayout or the lazy Windows measurement backend. Stored font settings
take precedence over defaults. No previous dimensions, origins or pin positions
are retained after modernization.

LEGACY_CURVE_PRECISION
Older symbol/footprint and PCB board ellipse modernization compares authored box spans
against the existing .3 shared-unit difference tolerance before floating-point
contour sampling. Exact
boundary decisions are stable under translation and normalized footprint scale;
binary floating noise does not decide whether a curve becomes a polygon. This
keeps the existing units and version gates. Controlled corner/scale sweeps around
the tolerance expose the rule; retaining exact boundary geometry avoids incidental
floating arithmetic changes without accumulating conversion drift. PCB board
curve decisions and imported picture dimensions also remain independent of the
caller's Decimal precision; picture dimensions use exact differences between
their sorted corners.

SCHEMATIC_DRAWING_DUPLICATES
TextLine is the current drawing text and TextAngle is its current orientation.
Sheet text has one current anchor. Import discards surplus sheet-text points
after older geometry has selected that anchor; its text bounds are calculated
from the retained position, angle and font settings. Empty geometry stays empty.
The normalization is quiet information and applies to DCH, ASC and DCHXML alike.
Public sheet-text fixtures with distinct extra points expose the normalization
through canonical import/reexport and subsequent stable point counts.
Modernized imports discard redundant Name/Orientation fields and earlier first
lines. Writers regenerate them. Generated-marking type tags are derived from
current Type and MarkingGenerated, without an older competing Type occurrence.
The placed DCH tag applies only to Type=10 with MarkingGenerated=true. Other
drawing kinds keep their type even when that option is set; cached definitions
use their ordinary type. Controlled public text fixtures varying those two fields
and canonical binary saves expose this rule without source-history metadata.
Default ASC compaction is the same for every import format; an explicit
compact_inactive=False context retains representable inactive content.

ROUTE_MODERNIZATION
Route normalization runs during every supported DCH, ASC and DCHXML import.
Its conditions depend on current geometry and attachments, not source version.
Verified short-route direction and redundant-handle rules apply to enabled nets;
an established overlapping-junction loading rule also applies to other nets.
Unknown or inconsistent attachment identities defer normalization with a diagnostic.
Normalization reconstructs established short-branch attachments. It is not a
general routing engine; longer or cyclic attachment constraints can remain
literal with a deferred-repair warning.
Loaded routes can include redundant coincident handles. The shared view
keeps endpoint direction hints and referenced points. Removed handles and previous
geometry are not retained in the model. Removed-point and junction snapshots
have no independent design meaning.
When a redundant coincident handle carries a segment attachment, its adjacent
direction hint can move onto that retained anchor. Identity links then project
the updated indices. No earlier geometry snapshot is retained.
The current geometry and references suffice.
Ordinary collinear vertices and unverified attachment cases remain unchanged.
Short free branches on straight host segments can be orthogonalized while
retaining endpoint identities. The host can contain other bends and coherent
pin anchors; its points, pin positions and segment identities remain fixed.
Pin-connected branches retain a coherent fixed pin endpoint. The stored incoming
direction selects the bend or projection before direction cleanup, rather than
reclassifying the source diagonal first. A perpendicular pin projection outside
the host uses a dogleg (a short right-angle detour). Nearby pins stay fixed.
An overlapping lead follows contiguous host segments to its departure point;
its identity reference retargets to the corresponding existing host segment.
Selected endpoint identities survive. Hosts settle before dependent two-point
branches, whose joins project onto the nearest settled host segment. This makes
repair independent of line-array order while retaining both pin and connection
identities. Ties use host segment order. Unresolved, cyclic, longer dependent or
unknown compatibility-direction constraints defer with a structured warning.
Repairs keep physical endpoints, authored free leads and valid attachment
identities, without introducing redundant zero-length handles. Reconstructing an
inconsistent input can change geometry beyond ordinary numeric rounding; the
settled result is stable under record reordering and repeated import. Already
consistent routes do not need such reconstruction. Ordinary authored bends remain
editable.
Two-point routes with pin or disconnected endpoints normalize their incoming axis
flag without keeping an earlier geometry snapshot. Wire/bus
attachments retain their direction hints until a verified attachment rule applies.
Independent net cleanup can proceed alongside unresolved bus-only data. Related
or unknown reference domains defer cleanup; structural edits are checked before
any point is detached. The import result is authoritative. Remaining
unsupported attachment transformations require implementation, not source backups.

NUMERIC_PRECISION
Each quantity has one authoritative numeric value. The separate calculation
value and source-biased binary arithmetic have been removed. Integers and
decimal values remain supported; ordinary floating calculations use the current
value. A uniform real-number type remains a separate simplification choice.
DCH and DIP numbers have four decimal places; XML has
explicit units and placement radians. Required quantization happens at output.
Range/type errors fail. Decimal XML unit conversion preserves decimal precision,
including half-grid coordinates. Component angles use their family's domain:
schematic placement degrees and PCB placement radians.
Exact byte identity and numerical or text-layout agreement are separate checks;
minor layout differences must not change identities, connections or accumulate
through repeated conversions.

The shared binary writer rounds once at the decimal 0.0001 step, using nearest
ties to an even integer step. It does not convert decimal facts through a float
before quantization. Python float inputs use their decimal spelling, consistent
with model number construction. The caller's decimal precision and rounding
mode do not select output. This is the library's rounding policy; storage
precision is the format constraint. Half-step results can differ from a floating
calculation by one stored step. Exact decimal projection avoids repeated bias
when a half-step local frame is centered again after import. Source properties
remain unchanged and no previous rounded value is kept.

Decimal XML unit scaling uses a local nearest-even calculation with at least
40 significant digits and 16 guard digits beyond the value's precision.
Trailing zeros do not select another numeric policy. On import, a shorter scaled
value is accepted only if converting it back exactly reproduces the incoming
XML number. Otherwise the full scaled value remains. This removes recurring
division tails without a tolerance, source history or a fixed precision cap on
authored coordinates. Lengths, areas and axis reversal use the shared converter;
ambient Decimal precision or rounding does not choose their interpretation.

Footprint Points_New and current text angles are authoritative. Readers consume
and discard redundant normalized coordinates and old text orientations after any
required legacy modernization. Writers regenerate these earlier representations.
Normalized coordinates can exceed the DCH writer's -100000..100000 range for a
small selection frame. DCH export bounds only these redundant coordinates and
reports dch-compatibility-range. Current Points_New remain unchanged. Physical
coordinates and other numeric fields outside their output domain still fail;
this is not a general permission to clamp design data.

DISPLAY_COLORS
Stored FontColor, Color and BrushColor are design facts. The model and writers
preserve them. An application's display environment can adjust colors that
match its canvas background while loading a document; such an adjustment is
not a format requirement or a reason to rewrite the stored colors. Compare
saved color values separately from environment-dependent exported appearance.

PAD_ORIENTATION_AND_MASK_MODES
PadAngle is the current footprint rotation in radians. Inverted is a generated
legacy output flag, absent from the shared model. Binary and ASC compatibility
flags have different rules: binary tests proximity to the positive upright
quarter turns; ASC indicates the legacy contour transposition. Their established
0.001-radian comparisons do not normalize or restrict the current pad angle.
The primitive binary writer always reads current properties, without selecting
saved occurrences or a source-version preservation mode.
Standard is one current choice independent of PadAngle. DCH import and output
keep it at any pad angle. ASC derives Standard=True only when that choice is true
and the angle is near zero; other rotations use explicit geometry and report
pad-standard-orientation as information. The source model remains unchanged.
XML import sets Standard from selection of the nonempty default pad style key,
using key identity even when another style has equal attributes. XML output keeps
an explicit style distinct from an equal default to preserve Standard=False.
A placed Side override remains independent of that selection. When Standard=True
accompanies explicit geometry different from the default, XML exports that
geometry with an individual style and reports pad-standard-style as information.
The source choice remains in the model; explicit geometry and angles are retained.
There is no shadow binary flag or earlier default-geometry snapshot.
ASC imports discard obsolete pad-number, size, shape, contour and swell/shrink
copies after resolving the current geometry. Writers regenerate those views.

DisableTopMask, DisableBottomMask, DisableTopPaste and DisableBottomPaste each
contain one current integer mode. Values 0/1/2/3 correspond to Common/Open/Tented/
By Paste for mask, and Common/Solder/No Solder/Segments for paste. DCH imports
resolve old booleans and later full modes into that one value. ASC imports discard
superseded boolean/state prefixes. Writers regenerate them from the current mode;
only mode 2 sets the old disabled boolean. No older boolean or mode occurrence is
retained. Current CustomSwell_New and CustomShrink_New remain independent values;
their older compatibility views follow the active mask/paste modes.

XML_ENUM_ALIASES
Named XML labels can merge several numeric source states. The Model3D unit
label Wings imports as -1. Drawing and component-marking alignment labels Left
and Top likewise import as -1 in their respective horizontal/vertical domains.
Equivalent numeric XML aliases modernize to the same -1 value during import.
Other numeric states remain literal; the rule applies only to these established
unit/alignment domains. DCH and ASC imports keep their own stored values.
XML export uses public labels on a detached view; spelling and the originating
numeric alias are available through optional source inspection, not model history.
This is equivalent normalization, without a notice for each aliased field.
Table alignment uses its separate Left/Center/Right domain and is unaffected.

INHERITED_DRAWING_WIDTH
ASC footprint drawings carry both Width (which can request an inherited pen)
and an earlier width in their compatibility header. The named Width replaces
that occurrence during import; if absent, the header becomes the current Width.
There is one editable pen setting, without an earlier display-width backup.
All exports use the current setting independently of edit history. ASC resolves
an inherited width through line_width(layer), defaulting to 0.1 shared units;
an explicit nonnegative Width controls both output occurrences. DCH and XML
retain the inheritance setting and use the receiving environment for display.
Changing application pen settings can therefore change inherited appearance;
the previous environment's calculated header width is not a design override.

XML_GEOMETRY_VOCABULARY
Library points use Points/Item in 4.3 and Points/Point in 4.9. Drawing text uses
Lines/Item in 4.3 and TextLines/TextLine in 4.9. Both import into Points_New/pt and
TextLine/pt. Export selects vocabulary by version. Duplicate alternative
containers and unknown row kinds fail instead of silently dropping content.

SPICE_MODEL_TEXT
ModelBody/Line stores ordered model strings, including blank entries. ASC uses
flat strings inside ModelBody and cl_ModelBody; the adapters map that spelling
to shared Line records. DCH and XML use their own string-list syntax over the
same values. Text restrictions still apply at the selected output boundary.

ABSENT_BINARY_FACTS
Public formats omit some binary revisions, compatibility values and settings.
Import supplies declared typed defaults where their absence has an established
meaning. A cross-format cycle cannot recover information absent from an
intermediate representation. A missing compatibility occurrence need not imply
meaningful loss when an equivalent state regenerates. No companion-file lookup
supplies missing facts.

ASC_TEXT_ENCODING
Encoding is an export context, separate from stored Unicode text and layout.
Default shared imports and exports use Windows-1252. A UTF-8 BOM identifies that
input encoding; other byte encodings require an explicit read/parse encoding.
Valid ANSI bytes are not guessed as UTF-8 merely because both decoders accept them.
The supported ASC dialect has no per-file codepage selector. UTF-8 output does
not establish that a receiving application will interpret those bytes as UTF-8.
Explicit byte encoding overrides the export context before projection. UTF-8
preserves representable Unicode through library cycles when selected explicitly.
Syntax inspection can retain its source codec; the shared model does not inherit
an output encoding from import history. Choose the receiving reader's encoding.
Windows-1252 best-fit substitutions warn and leave authoring text unchanged. Other
explicit encodings are strict; unrepresentable text is an invalid output request.
Quoted-text delimiter restrictions are independent of byte encoding and can still
produce asc-text-sanitization warnings. A redundant legacy cell Text field uses
asc-cell-text-compatibility info when TextLine provides the equivalent value;
restrictions on the actual line strings are reported separately. These are
current output policies, not a claim that every possible ASC encoding has the
Windows-1252 character repertoire.

ASC_RECEIVER_TEXT_NORMALIZATION
The receiving application's ASC reader replaces literal ! with spaces in placed
component names, RefDes, Value, Manufacturer, PartName, ModelString/ModelBody,
user-field names/values and sheet drawing text. The adapter reports
asc-reader-text-normalization as a compatibility warning for those fields while
retaining the literal punctuation. The library's own ASC reader preserves it;
DCH/XML avoid this receiver transformation. This is a receiver behavior, not an
inherent inability of an ASC string to contain !. Other strings have separate
reader rules; Datasheet does not receive this warning. The notice does not repeat
asc-text-sanitization when a quote or line break has just become ! on that export.

PCB_ASC_COMPONENT_HEADER
PCB ASC Component.Name is a quoted string; the following RefDes is an unquoted
text token. An empty RefDes omits that token. Numeric-looking names retain their
exact spelling, including leading zeroes. Quote marks supplied at the RefDes
position are literal name characters in the receiving application's import,
rather than string delimiters to remove. This differs from the component name
and from other document families' header rules.

Output uses an unquoted RefDes. Parentheses, ordinary spaces, quote marks and
line breaks cannot occupy that token literally: they become ! and produce an
asc-token-sanitization warning. The editable source is unchanged. Explicit
encoding applies to the token as well as quoted strings. A literal ! in either
PCB component-header field produces asc-reader-text-normalization because the
application reads it as a space. The library retains the literal !, consistent
with the ASC receiver policy above. Positional component/pad connections remain
independent of this name-spelling adaptation.

An external derivation uses small ASC fixtures differing only in the Component
header: an unquoted ordinary/numeric/empty RefDes, a quoted RefDes and literal
delimiter characters. Import and export to DIPXML expose the resulting RefDes
and distinguish its raw-token behavior from the quoted Name. Exporting a design
with a parenthesized RefDes exposes the canonical ! substitution. These variants
also distinguish preserved references from a change in displayed names. This
procedure does not claim that every proposed variant has already been converted
through the application.

PCB_APPLICATION_PREFERENCES
Settings.GridSnap, AssemblyWidth, CompOutlineWidth and CourtyardWidth are optional
application-preference snapshots in PCB ASC and DIPXML. DIP does not serialize
these four values. A DIP input therefore leaves them absent, without consulting
the machine's installed preferences or inventing authored choices. Text output
retains supplied values and leaves absent choices unspecified. Their absence in
a library-generated text file can differ from a canonical application export,
which may include that installation's current preferences.

DIP output reports application-preferences as a warning when explicit choices
are supplied, while retaining the authoring model. Reopening DIP uses the
destination application's preferences. This boundary concerns default drawing
widths and grid snapping, not existing geometry or its stored line widths.

An external derivation changes each preference independently, saves DIP and text
outputs, then reopens the DIP with different preferences or a clean installation.
The changed text values, binary comparisons and receiving preferences distinguish
an application setting from a stored design value. This procedure describes the
observable route without claiming a new experiment was performed here.

PCB_NET_ROUTING_PREFERENCES
Net.Width and Net.Clearance are independent routing preferences retained by DIP
and PCB ASC. DIPXML has no corresponding fields: its export reports
net-route-preferences as a warning for supplied non-inherited values, and XML
import uses the inherited -1 choice. Existing trace-point widths, coordinates,
class rules and endpoint references are separate facts and remain represented.
A large raw difference between a preference and -1 is not a changed trace width.

XML also omits ActiveLine/ActivePoint routing UI selections, reported as
active-route-selection information. These values are separate from committed
trace geometry and its connections. Missing fields in one destination do not
remove supplied values from the editable source.
DIP stores these two integer choices in ActivePoint, ActiveLine order. ASC uses
their named fields; the model exposes both by name, independently of wire order.
An ordinary ASC fixture with distinct valid selections, saved as DIP and exported
again as ASC, exposes the mapping. Changing one binary slot at a time and
repeating that conversion distinguishes the import and export rules.

An external derivation changes the net routing preferences while retaining
explicit trace geometry, then compares DIP, ASC and DIPXML conversions. Inspect
net attributes separately from each trace point's Width and coordinates. This
distinguishes an omitted preference from changed copper. A routing selection
can similarly be varied independently of the saved trace geometry. These are
observable procedures, not claims of newly performed application experiments.

PCB_ASC_LAYER_NAMES
Copper-layer names in Board/Layers/Name are unquoted text tokens. An empty name
has no token. The importer keeps numeric spelling, including leading zeroes,
and treats quote marks as literal characters. Every ! in this position becomes
a space, including ! inside quoted input. This rule is specific to copper-layer
names; other Name records and the quoted Units selection keep their own rules.

Export encodes ordinary spaces as ! without a loss notice because the layer
reader reconstructs them. Literal authored ! produces layer-name-spelling:
ASC cannot distinguish it from an encoded space. Parentheses, quotes and line
breaks become ! and produce asc-token-sanitization. The selected encoding also
applies to layer tokens. These changes affect the detached output spelling;
the editable name and layer identity remain unchanged. Layer connections are
written by identity and position, independently of this spelling adaptation.

An external derivation compares small ASC files whose layer headers use Top,
003, an empty token, Inner!!Layer!, and "Inner!!Layer!". Importing and converting
them to DIPXML exposes the exact names, distinguishes literal quotes from
delimiters and shows the ! substitution. A component/via linked to the renamed
layer tests identity separately. Exporting layer names with ordinary spaces,
literal ! and delimiters establishes the available output spellings. This is
a reproducible procedure, not a claim that every variant was already converted
through the application.

TABLE_TEXT_VIEWS
Cell.Text is the single authoritative editable string, including LF separators.
ASC's modern line list takes precedence during import and becomes that string;
the redundant older scalar and line-list view are discarded. DCHXML line lists
also import directly into Text. Writers generate their scalar/line-list forms
from the current string, without consulting source variants or edit history.
Import removes trailing blank rows containing only ASCII spaces, including the
last LF. Interior blank rows, spaces on nonblank rows, tabs and other whitespace
remain meaningful. This loading rule also applies to title-block cell contents.
It does not modify ordinary drawing text or retain an earlier cell string.
DCH and XML export the semantic text. This makes redundant legacy normalization
informational, while character substitutions in the current lines remain warnings.
ASC table ColWidths and RowHeights have bare headers; Cells carries its column
count. The grid and cell coordinates remain editable independently.

USER_FIELD_NAME_IMPORT
Enabled placed components modernize empty or ASCII-space-only user-field names
to Untitled during every supported import. Tabs, other whitespace and nonempty
names retain their spelling. Disabled components and cached definitions retain
their stored names. This is a current-name loading rule, without an earlier-name
backup. Authoring may still create an empty name; a subsequent import applies
the same rule. Global display preferences remain independent editable settings.

XML_EDIT_VALIDITY
Strings retain their source code units in the shared model. XML output rejects
characters outside XML 1.0 instead of replacing them silently. Invalid edited
output produces an error notice and raises; it does not alter the source model.
Optional XML syntax inspection separately validates comments, processing
instructions and the single Source element. Normal design editing and conversion
do not require a syntax view or retain that source structure.

INACTIVE_RECORDS
Enabled state and record data remain independently owned. ASC/XML projection
filters selected inactive record kinds; XML retains enabled flags where its
records support them. Removing a referenced record fails. Filtering occurs only
on an export view and reports inactive-records with the omitted record paths.
Empty inactive Undefined drawings with no text, geometry or identity association
produce inactive-empty-drawings info instead. Their unused appearance attributes
and slot positions are not meaningful design loss. Other inactive content and
unestablished retained variants remain warnings; no blanket cache classification
is inferred from an inactive flag.
ASC can carry these inactive states. AscExportContext.compact_inactive explicitly
selects retention or compaction; the default compacts independently of input format.
Placed footprint compaction removes disabled dimensions and inactive interior
pad, drawing and hole records. Pads are active when Number_New identifies their
current array position; drawings use a positive Type; holes use their enabled
flag. The first and last pad, drawing and hole boundary records remain.
Attachments follow their target identities through index changes. Cached
definition records are independent of this placed-record compaction. Retained
unresolved links still guard their target arrays; compaction does not invent
a replacement link.
XML keeps inactive nets, buses, page connectors and groups. Other inactive placed
records are omitted with a warning. Inactive cached symbol pins/drawings and
footprint dimensions produce inactive-library-records. The cached symbol's own
Enabled flag has no XML slot: its definition content remains exported, and
inactive-library-state reports the omitted activation state.
An omitted inactive source may own unresolved links: those issues are discarded
only from the export view along with the source, and the omission warns. An
incoming link from retained data still prevents removing its target.

GLOBAL_USER_FIELD_REGISTRY
Stored global user-field choices remain editable and are preserved by default.
An export context can request refresh_user_fields=True to rebuild choices from
enabled components in first-use key order. New keys use state 2 and position 7;
matching saved choices supply state and position. Omitted or replaced choices
produce global-user-field-choices information. Only the detached export changes.
This refresh is an explicit normalization request, not automatic import loss.

CACHED_SYMBOL_METADATA
Verification contains seven current boolean checks. Earlier shorter lists gain
false entries; longer lists consume and ignore obsolete extra entries during
import. Writers emit the current seven checks. No earlier list is retained.
ModelNote is an ordinary editable cached-symbol property. DCH writes it directly.
Current ASC/XML adapters omit nonempty notes with cached-model-note warnings;
this is a mapping limit, not an established inherent XML format limitation.
Cached Datasheet, pin SignalDelay and label-only choices are ordinary editable
fields. Current DCH/ASC mappings do not emit every cached XML field. Omissions warn;
XML data stays available for later XML output, separately from instance overrides.

SUPPLIER_DATA
Suppliers keeps SourceLocator, Prices/Quote and MainSupplier as independent typed
facts alongside PartNumber, Manufacturer, Pattern, Supplier and Currency. Current
ASC and XML projections omit the source locator and quantity/price rows. These
saved values are not recoverable from the converted file alone. Omission rules
warn once per kind, with affected paths, without changing the source. An external
supplier service might provide newer quotes, but that is not reconstruction of
the saved values. These are documented
projection limits, not a claim that every possible text dialect lacks such data.
MainSupplier is a cached match between Supplier and an environment's preferred
supplier, rather than an independently selected supplier. XML retains the chosen
Supplier and omits this flag with supplier-preference information. The original
cached bit is preserved in the shared model; reproducing it would require its
earlier environment, but it is not needed to retain the supplier assignment.
Cached ASC definitions also omit this match flag; placed ASC records retain it.
The shared omission reporter applies the same warning/information distinction
to each document family and destination, using affected field and quote paths.
Before schema 44, no MainSupplier flag is saved. DCH/ASC export supplies
False, or AscExportContext.default_main_supplier, for those absent flags and
reports supplier-preference-default information. Existing explicit flags win.
This is a declared fallback, not an inference from the supplier name,
locator or a local application's preferences. The imported model keeps absence.

PAGE_TITLE_GRIDS
Pages/Page/TitleBlocks/TitleBlock owns the selected name, dimensions, row heights,
column widths, cells and contents. DCH and XML preserve populated grids, including
an unnamed grid; XML omits empty default slots. ASC currently omits the definitions
and reports page-title-blocks. Rendered lines or text do not establish that the
editable grid definition can be recovered. Import does not replace the definition
with a drawing or discard an unnamed grid to match another exporter's policy.

FOOTPRINT_METADATA
Footprint Datasheet, RefDes prefix and default pad side remain separate fields.
Known DCH/ASC omissions warn and continue without changing source data.
Cached ASC footprints carry Datasheet directly; that field is retained through
ASC import/export. Embedded DCH footprints do not carry it.
An owned Pattern may have an empty name; this does not remove its geometry,
settings or pin-to-pad relationships. XML emits the complete definition under a
generated style key, including an empty Name. Complete projected content controls
sharing, including pad numbers and notes: equal physical geometry alone does not
make these definitions interchangeable. Clearing a name does not detach pad
identities or discard the record.
When no real local pads exist, an ordinary Pin.Number remains a literal value;
it does not create a missing link into an absent pad domain. Explicit unresolved
public pad keys remain guarded references. A newly populated target domain needs
ordinary explicit binding before subsequent reference-driven output.

EMPTY_PAD_SHAPE
XML can contain an explicitly empty pad-shape label. The shared PadShape,
PadShape_New and terminal Type contain integers. Import normalizes an empty main
stack label to5and an empty terminal label to-1, reporting empty-pad-shape as info.
Fiducial means20;5is an unnamed main shape. XML output generates the corresponding
empty labels naturally. Numeric aliases remain their supplied codes, including
otherwise unnamed values; output may use a numeric spelling to retain them.
An empty input does not reveal a previous numeric code, so none is reconstructed.
No source label or export-only shape override is retained in the model.

These conventions can be determined with small XML fixtures containing empty
main/terminal labels, named Fiducial and numeric aliases. Import each with
installed, licensed DipTrace and inspect the shape fields in its canonical ASC
output. Repeat XML export/import to distinguish an unnamed current value from
an earlier number omitted by an exporter. Numeric spellings also allow testing
each code independently of its display name.

PUBLIC_PAD_KEYS
XML pad keys and positional pad numbers are distinct facts. Imported pad keys
remain editable in Pad.Id. Within a real local pad domain, a missing assignment uses
Pin/UnresolvedKeys/Key("PadId", key), with Number=-1 and a scoped unresolved
reference. XML output preserves those keys without creating a false
link. Reordering the unresolved target collection requires resolving or clearing
the assignment first. DCH/ASC use positional IDs: resolved rekeying is info;
an unresolved assignment exported as unassigned is a warning. These rules leave
the shared source facts intact.

CATEGORY_REFERENCES
Component_CategoryName/Index and Pattern_CategoryName/Index retain classification
labels and local keys. CategoryTypes rows retain type/subtype names and keys.
XML import resolves available catalog labels; an unnamed reference can retain
its unresolved integer key without inventing a catalog entry. XML output keeps
that reference and allocates named category, type and subtype keys around the
missing keys in their respective scopes. Labels with an unassigned source index
still export as named classifications. These changes affect only the output view.
Declared catalog resources retain their keys, order and nested classifications,
including unnamed resources and equal labels with distinct keys. An unnamed
declared resource is distinct from an unnamed reference to an absent resource.
Component and pattern catalogs use separate scopes; nested keys belong to their
parent category or type. Redundant ASC catalog counts are consumed on import
and regenerated by that writer, rather than becoming shared model arguments.

STANDALONE_LIBRARY_RESOURCES
CacheLib/Patterns, CacheLib/PadStyles and PatternCategories retain unused resources
and labels. XML exports them. DCH/ASC warn when omitting standalone resources
that their embedded schematic representation cannot carry. An unresolved external
reference requiring an unimplemented resource mapping still fails.

ENVIRONMENT_AND_CALCULATED_MARKINGS
Font metrics, display choices, path aliases and picture resources are explicit
context overrides. Context is optional: stored settings are used first, then
standard mm/vector/font-size-2 defaults. Explicit marking styles affect only the
output view. DCH and ASC always rebuild generated label text and anchors from
current component text and label choices, independently of input format or
version. Points_New and TextLine may be absent on a generated label. Its drawing
record owns appearance settings; its calculated text and position never override
the label definition. Authored drawings retain their own placement and appearance.
FontType/TextShow selects literal text (zero), a component property (Name, RefDes,
Value, Part Name, Manufacturer, Datasheet), or a user field. Field-bound text is
refreshed on import and in every detached export view, including authored drawings.
Editing a component property therefore updates its bound text in every writer.
Inactive drawings and unknown binding kinds retain their current text. Name and
RefDes suffix choices use instance settings or the global choice. Global Common
suffix choices modernize to RefDes Show and Name Hide; component Common remains
an inheritance choice. Generated labels keep the suffix decision from layout.
Regeneration retains
existing drawing identities and never reuses inactive authored content or a
referenced empty slot. XML emits definitions without materializing these caches.
XML automatic marking definitions carry visibility and placement, with global
appearance settings. They do not carry individual generated-label FontColor,
PenWidth, LineSpacing, TextAlign, Locked, Group or unresolved local-key overrides. Differences from
fresh-label defaults and exported global color settings warn with
generated-marking-attributes; the source properties stay intact. Default or
equivalent settings need no loss notice. The supported application readers also
discard these overrides on their own XML export/reimport. XML symbol TextShow
drawings can retain individual appearance and bind component text, but use authored
geometry and visibility instead of automatic marking definitions. Export does not
silently substitute that different editing behavior. DCH and ASC retain the
automatic label's independent appearance; the authoring model remains unchanged.
The marking family uses an explicit context or stored Settings.MarkingFontName.
When neither exists, a single common family on active generated labels supplies
new labels and XML's global choice without requiring context. Empty and named
families together are ambiguous; existing individual choices remain intact.
A differing individual family that XML's global mapping cannot retain warns with
generated-marking-attributes. XML writes the global family even with vector text,
preserving the dormant system-font choice. DCH/ASC carry families on generated
drawings; a named global choice not recoverable from those drawings warns with
global-marking-font. An empty system family is valid and leaves font selection
to the receiving environment; callers can override it for reproducible layout.
None of these export choices changes the current authoring model.
FontType values for user-field labels are positional output projections of
marking-user-field identity references. Reordering a UserFields collection keeps
each label's appearance attached to the same field. A missing field remains an
unresolved local link; a later binding pass cannot silently assign another field
to its old literal index. Deleting or moving a referenced field requires explicit
reference editing.
There is no source-origin availability flag or manual marking refresh option.
System-font calculations use an injected TextLayout service or the lazy optional
Windows backend; vector calculations require neither. Unresolved required
resources fail rather than being fabricated.
The Windows backend measures with GDI and normal installed-font selection,
including bitmap/system faces; it does not force TrueType substitution. DPI is
an explicit backend setting. Vector layout uses character advance and line metrics
in an independent profile, without glyph contours. Those metrics are observable
from ordinary exported text rectangles; no application is needed at library runtime.
Pre-42 picture geometry modernizes during import into one anchor, current
dimensions and current text properties. Earlier corners and migration flags are
not retained.

PICTURE_SOURCE_REFERENCES
A picture source is a filename with an optional variable expression, an unresolved
companion-table reference, or unassigned. Picture_File/Picture_File_Variable hold
the filename form; BitmapIndex holds an unresolved companion index. An explicit
current path resolves that index. A blank path and index -1 represent unassigned;
there is no additional availability flag or historical source reference.
Import reads one supplied file and never searches for picture companions. An old
DCH index cannot recover a filename absent from that file. The picture drawing,
geometry and unresolved key remain editable. Exports use the current path or an
optional explicit legacy_picture_files table on a detached view and clear the
resolved index. A variable path may remain meaningful without an expanded path;
optional environment context controls path expansion.
ASC has a BitmapIndex field and can retain an unresolved integer through library
cycles. A warning identifies that current application readers do not resolve this
obsolete reference. DCHXML has no corresponding picture index; supported DCH output
schemas use file-backed pictures. With no resolution, these writers keep the
drawing and geometry, export an unassigned source, and report
unresolved-picture-reference as a warning. The authoring reference remains intact.
An already unassigned picture needs no loss notice. Invalid typed reference values
remain errors. Export never repeats geometry migration, discovers companions or
uses edit history to select a filename.

REFERENCES_AND_INCOMPLETE_LINKS
XML library groups accept an optional Enabled attribute, defaulting to true.
Import removes inactive group records and clears membership in those known
inactive groups, with local-group-normalization information. Active groups are
compacted without changing their members or geometry. A key that never named
a supplied group remains unresolved; it is not treated as an inactive group.
PCB XML output also omits inactive, unreferenced local groups with that
informational diagnostic on the detached export view.

The graph owns identities and retains original literal keys and scoped unresolved
values. Rebuild projects current indices and follows names by identity. Ambiguous
or incompatible edits fail. StringNumber and RefDes express hierarchy connector
names; ModelSig is independent. Wires can retain Page=-1 without being attached
to a sheet. Missing group IDs in an empty local group space remain unresolved;
missing local group/object keys in nonempty remapped spaces retain their literal
key in UnresolvedKeys/Key alongside an unassigned positional field.
The two key arguments are the field name and missing integer key. XML output
reserves those unresolved keys when allocating target IDs, preventing an absent
key from becoming a valid association. Related structural edits remain guarded.
DCH/ASC export unassigns the missing targets only on its detached view and emits
unresolved-local-reference. This applies to library groups, drawing-to-pad links,
ordinary dimension targets, internal-connection pads and symbol pin assignments.
There is one unresolved-key representation, including when copying an owned
definition into a placed instance; keys are reference facts, not source history.

XML_CACHED_SYMBOL_DRAWING_OPTIONS
Schematic and PCB XML library definitions retain active symbol drawing geometry
and text. XML has no cached ShowPart or MarkingGenerated field: non-default
values produce a cached-drawing-flags warning and import with false defaults.
Export leaves the current model unchanged. A cached drawing is not discarded
because it has a generation flag. This differs from calculated markings on
placed components, whose display geometry is regenerated from marking settings.
Wire-to-wire joins
resolve within their containing net. The redundant
ConnectB occurrence can disagree with that identity; import preserves its saved
value, and index rebuilding projects the current owner.
Bus-to-bus joins are similarly local. During DCH import, segment indices outside a resolved
route's valid range bind to its nearest valid segment, while retaining the saved
index until rebuild. Later reference binding does not infer clamping from import
origin. A route with fewer than two points has no valid segment.
Unresolved local joins watch their owner's route array and point arrays;
cross-bus joins also watch the bus collection. Unrelated collections remain
editable. Original unresolved fields can remain in output when those domains
have not changed. Related array edits require resolving or clearing the link.
Canonical renumbering also preflights the whole unresolved key: even with unchanged
record order, assigning positional keys can give a missing key an unrelated target.
Colliding renumbering fails before projected values change. Noncolliding numbering
and unrelated collections remain editable. The rule prevents accidental
reassignment without inventing repairs.
An existing unresolved source identity is not automatically invalid output.
Export with preserved one-point routes is not canonical topology repair or a
promise of exact agreement with application output.

DIMENSION_ATTACHMENT_SELECTORS
Footprint-local XML Connected/Object/SubObject/Point fields are typed facts.
Ordinary pad, shape and hole attachments use SubObject; Object is unused and
retained. XML public keys are mapped into the shared local identity graph.
Polyline and polygon drawing anchors use zero-based point positions. Terminal
attachments instead use a one-based real-pad ordinal in Object, a zero-based
terminal position in SubObject, and one-based polygon points in Point; zero
selects the terminal center. Nonpolygon and nonpositive terminal anchors retain
their literal anchor choice. These identities follow pad, terminal and point
reordering across all three exports. Boundary pad/shape/hole slots are excluded.

Schematic invalid or unknown selectors retain literal values and unresolved issues;
they do not make import fail. Known domains guard their own target collections,
allowing unrelated structural edits. Missing XML object keys in an empty target
collection remain unresolved; missing public keys in a nonempty local object
space use the separate unresolved-key representation above. The schematic
syntax-level XML view binds ordinary targets and drawing points; terminal selectors
remain unresolved there, scoped to their pad/style data. Unattached selectors retain their values
without target bindings. No coordinate repair or automatic detachment is applied.

PCB import uses the same local selector conventions with its own verified
attachment validation. Known invalid local targets become free coordinates,
with dimension-attachment-normalization information; unusable radius dimensions
can be removed by the validated loading rules. Unknown or unproved targets stay
explicit, guarded issues. A board drawing with an unavailable vertex can retain
its unresolved selector when no corresponding disconnection rule is established.
Board dimensions have additional net, pour, outline, component-origin and panel
domains; they do not reinterpret local terminal selectors as board attachments.
Component, net, trace, board-drawing and pour selectors are resolved through
their saved input keys before becoming current identities. They are not assumed
to equal input collection positions. Footprint-local positions have their own
boundary maps. Missing keys do not select unrelated objects at valid positions;
removal or compaction of an earlier object cannot change a surviving target.
The editable model exposes current selector views derived from its links, without
retaining the consumed saved keys. XML maps its footprint-local public member
keys into those local maps while retaining board object keys until binding.

This mapping can be derived from complete fixtures with nonconsecutive object
and trace keys, dimensions selecting each supported domain, and independently
reordered records. Canonical conversion exposes whether targets follow keys or
positions. Include a missing key equal to a valid collection position, an inactive
object, and a removed short trace before a retained target to distinguish correct
remapping from accidental rebinding. No source history is needed for these rules.
For PCB XML output, ordinary local members use public object keys, while terminal
owners still use real-pad ordinals. Reordering pads, terminals and polygon points
updates those selectors by identity without replacing their authored geometry.

PCB XML omits calculated marking text from placed physical drawing records.
If a local or board dimension attaches to such a drawing, export retains its
endpoint coordinates, writes an unattached endpoint and warns with
dimension-marking-attachment. The source attachment and drawing remain editable.
Only text with MarkingGenerated=true triggers this conversion; literal text and
non-text drawings retain their attachments. DIP and ASC keep the saved drawing
and dimension attachment. Generated-marking geometry omission itself remains
information, separately from the loss of a dimension's attachment relationship.

PCB_LEGACY_GENERATED_MARKING_IMPORT
Before PCB schema47, placed drawings tagged as calculated marking placeholders
are removed during import modernization. Current component/global marking
settings provide their replacement; the old rendering is not ordinary authored
text. The legacy-generated-marking diagnostic is information. Literal text,
including identical captions, is retained. Cached definitions have no placed
placeholder tag, and current representations retain their independent marking
data. This is a format condition, without name or caption matching.

An external derivation varies the generated tag independently of a literal text
record in copied older supported designs, then compares canonical import and
readable reexports. Controlled fixtures at the46/47 boundary distinguish the
gate, while identical text distinguishes tag-based normalization from caption
heuristics. Older binary fixtures can be read by current licensed software;
producing these observations does not require an older application. This is a
concrete derivation route, not a claim of a new canonical conversion experiment.

PCB_CALCULATED_MARKING_GEOMETRY
Placed components may have marking settings without calculated text drawings,
notably after XML import. DIP and ASC export construct absent drawings on the
detached output view. Visibility, side, explicit or automatic placement, named
text and ordered custom fields come from current marking data. Supplied drawings
and their dimension attachments retain their identities; literal bound text is
independent. Unplaced library definitions are not given placement captions.
XML continues to carry marking settings without these calculated drawings.

Generation uses the shared text services and stored global or component font
settings. ExportContext.text_layout can supply system-font measurements; vector
layout is self-contained. When an optional drawing needs unavailable font
measurements, export retains the settings and reports
calculated-marking-font-resources as info, allowing the receiving editor to
reconstruct it. Successful construction reports calculated-marking-geometry as
info. Neither path changes the author's document or invents measurements.

For absent global settings, library output defaults show only the silk RefDes
and use automatic alignment. Stored choices, including zero-valued choices,
take precedence. These are deterministic library fallbacks, not a claim about
installation preferences. Visible empty values remain visible labels and can
occupy an automatic placement slot.

The behavior is externally derivable using named and custom-field text fixtures:
vary visibility, alignment, body dimensions, side, angle and font, then compare
calculated caption records in canonical ASC conversions. Distinct text reveals
role priority and explicit/automatic ordering; blank visible fields reveal
occupied slots. Coordinate differences expose edge anchors and stacking ratios.
An angle sweep with a following automatic caption exposes edge-choice changes.
Supplied literal/generated drawings and attached dimensions distinguish missing
geometry reconstruction from replacing existing authored selections.

SCHEMATIC_ANGLES
The model accepts finite angles beyond a full turn. All schematic writers
normalize modulo one turn and round to the nearest quarter, with half-way ties
to an even quarter. Output uses either an orientation 0..3 or a clean angle.
Placement uses degrees; drawing/label angles use radians. Projection leaves the
authoring model unchanged and can report schematic-angle-normalization as info.
Footprint pad/dimension and 3D angle domains are separate and are not quantized
by this schematic policy.

GEOMETRY_AND_IMPLEMENTATION_LIMITS
XML placement uses a finite discrete-orientation calculation. Small and negative
angles retain their literal angle with unrotated definition geometry. Positive
angles select a quarter orientation after full-turn normalization. The component
Angle records this interpreted placement. No original-angle or placement-angle
backup competes with it. All writers use the current angle. Some positive angles have
no terminating discrete orientation and produce a bounded input error.
Unknown attachment modes retain literal selectors and unresolved-reference
guards; their target semantics cannot be inferred. Unrecognized named XML enum
labels and unsupported public fields still need an explicit mapping. Missing
nonlocal styles or required resource definitions remain import errors.

XML_LIBRARY_FONT_STROKES
-----------------------
Library text and dimension strokes use physical lengths from application
5.3.5.0 onward. Earlier positive strokes use the unscaled value; the standard
negative presets remain -1/-2/-3. Other older negative choices normalize to a
supported preset after unit conversion. Component and pattern library headers
supply their respective versions and units, independently of the outer document.
Import resolves these choices into one current stroke value; export applies the
selected XML dialect. No source-era flag is stored in the model.

The distinction can be established with ordinary text/pin/dimension fixtures:
choose a positive stroke and a negative preset, convert library data in mm, mil
and inch, and compare the values before/after the version boundary. Nested
libraries with different units distinguish the owning scale. Controlled copies
that change only the library Version header let current licensed DipTrace expose
the earlier loading convention through canonical ASC/XML conversions; this does
not require installing each historical application. Portable fixtures
exercise this boundary and old/current output against the same current values.

POUR_FILL_PRESENCE
-------------------------------------------

CopperPour.Poured is the filled choice. Optional Fill owns supplied calculated
geometry: absent Fill means unavailable, while an empty Fill is an available
empty dataset. Neither state calculates copper or changes the authored boundary.
ASC and DIPXML can retain Poured without Fill. DIP requires its saved filled
choice to have a Fill dataset: export projects missing Fill as unfilled and
reports pour-fill-unavailable as info. The source model remains unchanged.
DIPXML omits supplied calculated Fill with info; boundary and settings remain.
This reconstructable omission is separate from losing an authored pour definition
or settings, which requires a warning.

POUR_REGION_CLASSIFICATION
--------------------------------------------------

Fill/Regions is an optional calculated classification dataset. Its Region records
own nonnegative Number labels unique within that Fill. Fill primitives reference
these identities through nullable Region; read-only RegionId derives the current
Number or -1. The groups do not reference individual polygon contours and do not
calculate or validate copper geometry.

Absent Regions means classification is unavailable. Present, empty Regions means
classification is available with no assigned groups. Present Regions can also
contain groups alongside unassigned primitives. Thus a primitive's Region=None
does not by itself imply unavailable classification. Editing a group Number
updates every member's output label. Cross-fill references and duplicate labels
are rejected atomically. Referenced groups require explicit disconnection before
removal, following the ordinary relationship-removal policy.

DIP and ASC import consume their saved classification-validity indication.
Valid classification becomes Regions and member references; negative labels
become unassigned members. Invalid classification becomes absent Regions, without
keeping stale positive labels. Existing binary import gates apply, including
classification invalidation before schema 38. Geometry, settings and Poured
remain; pour-regions-unavailable is info, since a geometric editor can reconstruct
classification. The library does not perform that calculation.

DIP/ASC output derives validity from Regions presence, independently of whether
every primitive is assigned. It writes each member's current Number or -1.
Available empty and available partly unassigned classifications remain distinct
from unavailable classification. Unused Region labels have no independent record
in these formats: unused-pour-regions warns when omitting them. DIPXML has no Fill
classification records; its calculated-fill omission covers the whole dataset.

External derivation: small filled-pour fixtures exported to ASC expose primitive
group labels and Regions_Counted together. Controlled ASC copies can vary only
the validity indication or labels, then be reopened and converted using licensed
DipTrace. Available unassigned labels, invalid stale labels, grouping independent
of polygon order, and binary revision behavior can be distinguished this way.
The portable tests additionally construct these variants directly and verify
reference edits, raw output validity and all supported binary output profiles.

XML_PAD_HOLE_SETTINGS
---------------------
Physical pad-style XML can carry HoleType, Hole and HoleH even for a surface
style or round hole. These are independent stored settings; surface/round mode
does not erase them in the model. Writers include both dimensions, avoiding
unnecessary loss when moving between formats. A missing XML HoleH inherits Hole;

An external check can use an ordinary XML pad style with distinct Hole/HoleH
values, attach it to a pattern pad and convert to ASC. Surface and round variants
expose the retained settings there. Removing HoleH from the XML distinguishes
the inherited height from an explicit zero. No external file lookup is needed.

XML_PAD_INACTIVE_GEOMETRY
-------------------------
Pad-style MainStack can retain Corner, XOff, YOff and Points independently of
the selected Shape and surface/through mode. Terminal styles likewise retain
Corner and Points independently of their selected Shape. These settings can
become relevant after a later edit; XML output preserves supplied values rather
than clearing them when another geometry is selected. Missing corner/offset
attributes mean zero, and missing point collections mean no supplied vertices.
No source backup or additional availability flag is involved.

The shared writer applies this rule to default and individual styles in both
schematic and PCB XML. Active geometry and the stored shape selection remain
unchanged. Empty collections and inactive zero settings need no XML spelling.

An external derivation can start with an XML style using Ellipse, nonzero Corner
and offsets, and distinct Points/Item vertices. Attach it to a pattern pad and
convert to ASC with installed, licensed DipTrace to inspect the independent

also allow the inverse conversion to be checked. These are concrete measurement
procedures, not a claim that every controlled variant has been run.

XML_LIBRARY_SUBFOLDERS
---------------------
Component-library XML carries folder labels as ordered SubFolders/Item text and
each symbol's selection as SubFolderIndex. These map to
CacheLib/Subfolders/Folder.Name and Part.SubfolderIndex. Folder names remain text,
including numeric-looking labels, empty labels and duplicates. A missing symbol
selection defaults to -1; nonnegative indices remain explicit values, including
when the XML omits its folder list. No external library lookup supplies missing names.
The shared XML library mapping preserves both labels and selections. Empty folder
collections need no output element, and output does not alter the source model.

An external check can create two component-library folders, assign a symbol to
the second and export XML. Renaming that folder changes its Item text while the
symbol's zero-based SubFolderIndex remains 1. Converting the library to ASC
exposes the same labels and index.

SCHEMATIC_BINARY_EMPTY_LIBRARY_SLOTS
----------------------------------
The shared library-slot model allows no definitions, but current schematic DCH
requires at least one definition in every stored slot. DCH schema45 and later
input rejects a slot with no definitions; every supported output revision has
the same requirement. Add a definition or explicitly remove an unused slot
before writing. Export does not invent a symbol or footprint, discard a slot's
references or change the authoring model to meet this requirement.

Earlier DCH schemas34..44 can contain empty slots. Import keeps their position
but clears the unused trailing literal library path, reporting the quiet info
unused-library-path. No definition owns that path. This normalization is
schematic-specific; the shared model and other families keep their own rules.
ASC likewise needs nonempty cached definitions. XML can represent an empty
entry with the path omissions described below.

Controlled cache sections with zero versus one definition and distinct following
path/project fields provide an external check: canonical loading/conversion can
distinguish the earlier empty-slot framing from the current definition-owned
paths. This is a discovery procedure, not a claim of a performed experiment.

XML_EMPTY_LIBRARY_SLOTS
-----------------------
An empty CacheLib/Slots/Slot remains an empty XML Component entry, without a
synthetic Part or physical definition. XML import accepts that entry; a placed
component referring to a missing Part remains an import error.

Slot.LibPath and Slot.VariablePath normally project to a Part's LibPath/Path
and LibPath/Var. Without a definition there is no XML owner for these paths;
nonempty values produce empty-library-path warnings. An independent
Slot.Model3DFile_Variable likewise has no XML field and produces
unattached-model-path. Physical definitions retain their own model paths.
Empty metadata is quiet. These exports leave the authoring model unchanged.
The omitted paths cannot be reconstructed from that XML alone.

The capacity can be determined with an empty cached component carrying library
and 3D model paths, contrasted with a component containing one Part and a
physical definition with its own model path. Canonical XML conversion exposes
the empty Component, the Part-owned library paths and the physical model path.
Reopening the XML distinguishes retained metadata from omitted metadata.

PCB_PLACEMENT_COORDINATES
-------------------------
The PCB model's placed physical coordinates describe the actual
placement side. Cached footprint definitions retain their library coordinates.
XML separates reusable library geometry from placement, so its reader reflects
bottom-side physical data into the placed frame. Placement X/Y, angle and the
independent Flip/HorzFlip choices remain separate facts; a flip flag is not used
as a substitute for Side.

The reflection covers pad centers, copper offsets, polygon points and angles;
terminal geometry; paste rectangles; drawing points, text horizontal alignment
and angle; hole centers; local dimension X coordinates; and the footprint origin.
It retains record identities and ordering. Default-pad settings, marking settings
and 3D model data remain in their respective scopes. XML's Y-axis/unit conversion
is a separate mapping.

XML output applies the inverse view to physical styles and placement options.
Standalone physical projection helpers use that same view. No source fields,
relationships or caches are mutated, including when projection fails. Ordinary
frame conversion is quiet; it is not data loss or a repair diagnostic. Nominal
size and recentering use the separate mapping below.

An external derivation uses an asymmetric footprint with separately numbered
pads, a nonzero copper offset, a polygon terminal, a text anchor, a local hole,
a dimension and paste rectangles. Place it on each side and compare canonical
DIP/ASC placed coordinates with XML's physical style and placement options.
Vary Side, Flip and HorzFlip separately, and reopen controlled XML copies to
distinguish side installation from stored editor choices. Include a cached
definition to establish which geometry remains independent of the placement.

PCB_LEGACY_TEXT_PLACEMENT
-------------------------
Before DIP schema47, footprint text uses a normalized box and quarter-turn
choice. Bottom-side placement selects the opposite horizontal box corner as
its current text anchor. This is independent of the saved Flip choice. Cached
footprint definitions retain the top-side corner selection. Other drawings do
not acquire an additional reflection from this text-only conversion.

Older component marking slots resolve in saved order. When both slots select
the same label, a later explicit edge choice can replace an earlier explicit
position. The current model contains one named label placement, with its normal
alignment and coordinate fields; it does not retain competing historical slots.

To observe these rules, convert an asymmetric older text footprint at each
quarter turn on both sides, varying Side and Flip separately. Compare its
normalized controls with ASC/XML text anchors and include a cached definition.
For marking precedence, select the same category in both old slots, give one a
distinct shift and the other an explicit edge, then swap their order and compare
the named fields produced by ordinary conversions. These are external discovery
procedures; they do not imply that every fixture combination was measured.

PCB_FOOTPRINT_FRAMES
--------------------
PCB import derives placed footprint nominal sizes and local frames from current
physical geometry. Bounds include main pad copper, non-text footprint drawings
and enabled mounting-hole outer diameters. Text, stroke width, terminal extensions
and ordinary pad drills do not enlarge this body envelope. Unknown or empty
copper outlines contribute no envelope. A zero or empty nominal extent uses
0.001 shared length units.

Recentering translates active physical anchors, the ordinary footprint origin,
local dimension coordinates and explicitly positioned component/user markings.
It compensates component placement so board geometry stays in place. Common or
automatic marking positions and 3D offsets remain independent. Mounting holes
and static vias retain their initialized zero independent origin. Every nonzero
translation is compensated, including sub-display-precision offsets; no renderer
rounding cutoff is used to move design geometry.

Angular bounds use reflection-consistent rotation factors: equivalent reflected
angles share one reduced magnitude and opposite sine signs. Exact quarter turns
keep integer rotation matrices; nearby continuous angles are not quantized to
those turns. Coordinate reflection retains Decimal values without ambient
precision loss. These are calculation rules, not extra authored model fields.

Binary output keeps an already representable centered frame. Where rounding
would change that frame, it expresses local coordinates around an authored
origin, or another current physical anchor if the origin exceeds the destination
range. Placement compensation uses the destination's rounded component angle.
Loading reconstructs the centered model without retaining an earlier wire frame.
This prevents repeated rounding and recentering from walking a rotated component
across the board. Explicit local markings and dimensions use the same translation;
net identities and existing board traces stay independent. The output-only
adaptation emits binary-footprint-frame info. Normal scalar/angle precision limits
still apply; this does not promise arbitrary source-byte reconstruction.

Common fiducial visibility uses the stored ShowCompFiducials choice, falling back
to ImportContext.show_component_fiducials (True). Individual Show/Hide choices
override Common. A standalone fiducial contributes its own physical geometry.
The resolved common setting remains editable model data so output does not
silently select another loading environment.

XML first constructs a placed physical template frame, without altering cached
definitions or incoming placement/marking coordinates. Actual placement-side and
per-component settings are then installed. Shared finalization runs after via
styles supply physical sizes and before validating Standard pad declarations.
Export recalculates the same derived frame on a detached view after data edits;
ordinary editing does not require a manual rebuild.

An XML output style uses the common visibility frame at construction. Its
placement and explicit marking coordinates compensate that change, leaving the
individual Show/Hide choice intact. Final import then restores the component's
own frame. This also preserves board positions when the individual choice differs
from the common setting; writing an individually centered style with unchanged
placement coordinates would otherwise lose its construction displacement.

The external derivation uses asymmetric main copper, remote text, wide strokes,
a mounting hole and a dimension. Canonical conversion exposes changes to nominal
size, origin, local anchors and placement. Vary fiducial visibility and explicit
versus automatic marking alignment separately. Noncentral XML templates with
supplied placement coordinates distinguish construction from finalization.
Physical pad positions and repeated conversions distinguish stable normalization
from accumulated movement. Analytic shape bounds use ordinary geometry rather
than a renderer's sampled outline approximation.

PCB_UNAVAILABLE_COPPER_GEOMETRY
-------------------------------
Placed PCB pad width and height can independently be None when physical copper
geometry is unavailable. There is no second availability flag or retained source
marker. A selected via style or an explicit edit can supply the missing values;
removing a style retains the latest materialized geometry. Unavailable copper
does not contribute a body envelope; identities, positions and connections stay
available for inspection and editing.

Adapters consume the negative-one scalar marker and generate it again where the
destination requires a numerical field. Recognition uses the destination scalar's
binary64 boundary, including XML unit conversion, without a general negative-size
clamp. Import/export reports this equivalent representation as information.
Shared library-footprint constraints remain separate from nullable placed PCB
geometry. The observable route is an XML via placement without a selected style,
contrasted with the same placement selecting a known size/hole style; canonical
exports expose constructor dimensions and style-supplied physical geometry.

PCB_OBJECT_CLASSIFICATION
--------------------------
Current physical content determines standalone PCB classifications. One ordinary
pad becomes Pad (retaining an existing Via classification); one fiducial main
shape becomes Fiducial; one enabled mounting hole becomes MtHole. Text does not
prevent these classifications, while additional non-text physical objects do.
Incompatible Pad/MtHole/Via classifications become Free. Other compound types
are retained rather than arbitrarily becoming Free.

Import applies this rule before binding the editable model. Export applies it
to the detached view using normal model edits, including automatic reference
ownership updates. Adding non-text geometry to a selected via can therefore
produce a Free object without losing its geometry, connections or style reference.
Its dimensions become independent of the selected via style. Removing that
geometry later does not restore a remembered historical Via classification.
Classification changes report standalone-object-normalization as information.

MtHole, Via and Fiducial initialize named and custom component marking Show
choices to Hide. Changed import choices are normalization information. Export
reports standalone-marking-visibility as a warning if current choices would be
lost, while retaining text and relative placements. The authoring model remains
unchanged. A concrete observable derivation varies pad/hole/drawing counts and
text versus non-text drawings in controlled public text inputs, then compares
canonical classifications, marking choices, geometry and endpoint identities.

PCB_STANDALONE_OBJECT_DATA
--------------------------
Canonical loading initializes component-only settings on mounting holes and
static vias. Their footprint origin becomes zero; hierarchy paths, assembly
exclusions and authored internal pad-pair definitions clear. A via additionally
has no 3D attachment: file paths, transforms and generation settings reset to
the shared model's empty-attachment defaults. A mounting hole retains its 3D
attachment. Ordinary components and independent cached definitions retain these
facts. Do not generalize this rule to every standalone pad or fiducial.

The shared importer performs this initialization before relationship binding.
XML also applies its construction rule before subsequent object classification
and side conversion; a later change of classification does not restore data
already ignored during that construction. Changed input reports
standalone-object-data as info. No obsolete values remain as source backups.
Empty 3D attachment uses the library's shared constructor defaults rather than
unavailable renderer or resource state.

The editable model can still contain independent values in these fields. Export
warns with standalone-object-data when a receiving editor will initialize them.
These fields may be serialized, but reopening does not preserve those settings
for the special object. Export does not change the authoring model. Authored
pad geometry, connectivity and independent flip/placement choices remain.

An external derivation creates a one-pad via and a mounting-hole layout with
distinct origin coordinates, assembly choices, hierarchy/pad-pair entries and
3D file/transform settings in controlled ASC/XML inputs. Canonical load/save and
text exports expose which fields initialize and distinguish the hole's retained
3D attachment from the via's empty one. Include an ordinary component and a
cached definition as independent controls. A declared XML via with several
physical objects distinguishes construction from subsequent classification.

PCB_XML_PAD_INHERITANCE
-----------------------
An ordinary placed XML pad with no DefStyle declaration infers Standard from
its current physical geometry, applicable mask/paste settings and terminals.
Inference occurs after placed-side installation and uses the same default-style
comparison as ordinary import validation. Only supplied placement pad rows
participate; an unlisted pad keeps its template declaration. A fiducial pad
does not use this inference. Resolving an omitted declaration is quiet.

An explicit placement declaration takes priority over inference. Subsequent
common import validation can still clear a contradictory Standard=True. Selected
via geometry is installed before this validation, so temporary constructor or
earlier local dimensions do not incorrectly clear a valid declaration. Vias
skip the XML inference step: omission keeps their constructor's custom status.
Separate cached definitions retain their own style declaration.

The current XML dialect writes DefStyle on every placement pad as well as on
physical definitions. Earlier supported dialects omit it. They can change an
independent custom choice on an ordinary pad whose settings equal the defaults;
via pads initialize as custom instead. Export reports pad-style-inheritance
as a warning only when those receiving rules change the current selection.
Geometry is retained and the source model is unchanged. Style-key separation
still preserves independent cached definitions; it does not prevent a placed
pad's geometry-based inference.

To derive this rule, use equal default/individual physical styles with a custom
declaration, then vary the placement's DefStyle between omitted, Y and N. Reopen
and convert to ASC to inspect Standard. Repeat with an independent mask override,
a fiducial pad, an unlisted pad and a Via placement. Canonical exports in the
selected XML versions expose when the explicit placement field is available.
Distinct saved via dimensions and selected style dimensions establish that
style installation precedes the common status check.

PCB_NEW_COMPONENT_LINKAGE
-------------------------
A newly authored PCB component starts with HiddenId=-1 and no hierarchy steps.
Identifier zero is a valid schematic update key, so it must not imply an initial
association for a component created without a schematic. Importing an explicitly
supplied key, including zero, retains it. No additional linked/unlinked flag is
needed; export represents the same association in the destination's fields.

This convention can be derived by placing a component directly in a new PCB,
then saving and converting to ASC/XML without importing a schematic. Inspect
HiddenId/UpdateId and HierarchyPath, and compare with a component transferred
from a schematic whose persistent identifier is zero.

PCB_ASC_DRAWING_ANGLE
---------------------
Current PCB ASC imports TextAngle as the authoritative board-drawing angle.
When it is absent, the integer Orientation supplies the numeric angle directly;
when both are absent, the angle is zero. This fallback does not multiply by a
quarter turn or transform existing point geometry. The editable model retains
only TextAngle; output derives the redundant compatibility Orientation.

This mapping can be derived using a current ASC text drawing with distinct
TextAngle and Orientation values. Remove TextAngle, reopen and export, then
inspect the resulting TextAngle. Repeat with an Orientation value such as 1
that distinguishes direct numeric use from quarter-turn conversion, and with
both fields omitted. Existing point coordinates provide the geometry control.

PCB_XML_BOARD_DRAWING_DOMAINS
-----------------------------
XML emits board-drawing font style only for ordinary text (Type 6). FontName
and TextLines belong to the text-bearing kinds 6 and 10. Picture alignment and
image settings belong to pictures (Type 7); ordinary geometric drawings do not
acquire font or picture content from inactive binary slots. The output leaves
those source values unchanged and does not strip characters from authored text.
XML-invalid characters in active text remain errors. Omission of unused fields
is an ordinary projection of the current drawing, without a loss warning.

An observable derivation varies a drawing's kind while keeping distinct font,
text and picture settings in controlled ASC/DIP inputs. Canonical XML exports
expose which fields each kind supplies. Include separate text and picture
controls to distinguish meaningful content from inactive properties. Numeric
kind 10 retains its text body and TextAlign without ordinary text styling.

PCB_STATIC_VIA_STYLES
--------------------
The PCB adapter resolves an active static via's physical geometry
from its valid selected ViaStyle during DIP, ASC and DIPXML import. This sets
the pad's circular copper size, circular hole, zero corner radius and shape offsets;
the style's copper span supplies its BlindLayer exclusions. Through vias have
no excluded copper layers. The footprint's size fields follow the style size.
This refresh retains pad identity, connections, position, labels, angle, mask/paste
and thermal settings. Ordinary pads and vias without a selected style do not
use this normalization. No previous geometry is kept as an alternate truth.

Import reports changed geometry as static-via-style info. In the editable model,
the component's via-style relationship projects Size into the pad's width/height
and the footprint's four size fields, and HoleSize into the pad's hole dimensions.
These managed values follow style edits and retargeting automatically. Its
BlindLayer rows likewise follow the selected span and copper-stack ordering.
Rows retain their identities while their excluded layers remain applicable.
Edit the style to change controlled data; independent contradictory assignments
are rejected. Removing a derived row that has an external user also fails before
the span changes. Changing type or disabling the component releases the
projections. Removing the style leaves the latest geometry and layer rows as
independent data; reactivation restores the projections. Invalid transitions
fail atomically, without requiring a rebuild. Ordinary pad layer choices remain
independent. Existing constraints on deleting referenced layers still apply.

Export retains a static-via-style warning for contradictory internally assembled
content that the receiving editor would replace. Normal model operations prevent
those contradictions. The authoring model remains unchanged by export.
An explicit XML PatternStyle does not prevent this selected-style refresh.

An XML via supplied by its ViaStyle without a nonempty PatternStyle has Through
mounting (Mounting=0). An empty PatternStyle is equivalent to omission. A nonempty
style retains its own Mounting and LockTypeChange; cached definitions remain
independent. Compact XML omits a physical style only when its implicit defaults
reproduce the current physical data. Other mounting choices or a type lock
therefore require an explicit style. This can be derived by importing small
XML via fixtures with omitted/empty style keys and contrasting them with explicit
None, Through, SMD or Mixed mounting and Y/N type locks, then comparing ordinary
ASC/XML conversions. Unknown nonempty styles still fail to resolve.

XML physical library patterns use the shared pattern-type vocabulary (Free
through IPC-7351), separately from PCB placement types such as Pad, MtHole, Via
and Fiducial. A placed object's PCB-only kind projects to a Free physical style;
its component Type retains the classification. This equivalent projection is
xml-physical-pattern-type info. An unplaced physical definition has no component
Type to retain that kind and produces a warning instead. Physical data and
explicit LockProperties remain. Canonical XML exports may lock these generated
styles; the library retains the supplied lock choice because XML can express it
independently. Import does not change explicit lock settings merely to match a
generated companion. Compare ordinary ASC/XML exports of controlled standalone
objects, then vary their physical styles' LockTypeChange independently of their
placements' Type to derive both the vocabulary boundary and the retained data.

The rule can be derived with a small via board by assigning distinct copper
and drill dimensions to the selected style and its placed pad, saving controlled
DIP/ASC/XML inputs and reopening them before canonical conversion. Varying pad
shape, angle and offsets independently identifies the affected fields. Contrasting
a through style with an inner-layer span identifies the excluded layers, while
independent mask and thermal edits distinguish the options which remain local.

Cached footprint origin-display choices and Model3D.AutoColor are independent
settings, including in an empty named or unnamed footprint. XML carries them in
Origin and Model3D attributes. Generated style sharing must account for these
settings as well as geometry; equal geometry alone does not justify combining
different definitions. Import and export retain the supplied choices. A
canonical conversion can change these attributes while building shared styles;
that does not establish a format limitation or justify discarding representable
values. Derive their independence with two equal footprints whose Cross, Circle,
Common, Courtyard or AutoColor differs, inspecting the public attributes and
style links before and after conversion. Empty footprints provide a separate
control, without assuming that an empty name means an absent definition.

Symbol custom fields and footprint-template custom fields are separate ordered
lists. XML carries both under their owning Part/AddFields and Pattern/AddFields;
neither list supplies a replacement for the other. Field names, values and
text/link types participate in physical-style equality. Cached and placed
footprint classifications likewise remain independent. A canonical XML export
may use symbol fields in a generated physical style or share a placement's
classified style with a cached footprint. Keep the original independent data
where XML can express it. Controlled equal-geometry definitions with different
custom fields or classifications, and distinct placed overrides, expose these
namespaces through ordinary ASC/XML conversion and their explicit style links.

XML via-pad initialization is separate from that selected-style refresh. Pads
come from ordered placement rows even when PatternStyle supplies a physical
template. Each receives a generated StringNumber starting at "1", a blank Name,
zero X/Y and PadAngle, and default locking, side, group, corner and contour data.
Placement keys bind net/other references before regeneration; they are not
retained as a second identity. A key is optional for an unconnected pad.
Duplicate supplied keys remain errors. Independent cached definitions remain
independent of the new placed pads.

Placement NetId, InternalConnection, mask/paste, layer and thermal options still
apply. The selected via style subsequently supplies the circular physical size
and span described above. Without that style, the XML pad initialization defaults
are width/height -1 and round hole dimensions 0.5 in shared length units.
Import records xml-via-pad-initialization as info. Export warns with
xml-via-pad-data about independent values this process replaces, even if an
explicit physical template can spell them. Local pad labels, positions and angles
survive DIP/ASC import; they cannot override XML via initialization.

An external check can give a physical template's pad a distinctive name, number,
position and locking, reference it from a Via component, and use a different
placement Pad.Id in its net membership. Reopening and canonical export distinguish
the template data from generated placed data. Removing the style selection and
varying the placement options independently exposes the initialization defaults.

PCB_INTERACTIVE_ROUTING_STATE
-----------------------------
DIP schema 53 onward can contain an additional interactive routing-session
block. Ordinary document import consumes and validates its scalar values and
nested collections, then clears the session. It retains neither preview paths
nor selection/undo snapshots as authored board data. Committed trace geometry,
endpoints and differential-pair geometry are read from their own board sections.

PCB_FILLED_BOARD_DRAWING_IMPORT

PCB_UNUSABLE_TRACE_IMPORT
-------------------------
PCB import removes ordinary traces with fewer than two points. It also removes
two-point paths shorter than 0.001 shared length units when an end is free and
no other ordinary trace uses that path as an endpoint target. The distance is
Euclidean and the bound is strict. Longer paths, paths with both ends connected
and paths used by another ordinary trace are retained. Separate differential
geometry has its own ownership and is not selected by this ordinary-path rule.

Cleanup frees references to removed paths, clears their pair selections and
associated calculated teardrop polygons, and preserves surviving coordinates.
Current selectors regenerate from surviving identities. The library applies
the same eligibility rule until stable, making unused chains independent of
their input ordering and preventing progressive loss over repeated conversions.
It reports unusable-trace-normalization as import information. No previous
geometry or deleted handle is retained. Ordinary data edits do not run cleanup.

An external derivation uses complete ASC/XML fixtures with a free-ended
two-point trace and a distinct retained route. Canonical save/reopen through
DIP exposes the normalized trace list and endpoint choices in ASC/XML. Vary
length below, at and above the bound, including diagonal coordinates; compare
zero-, one-, two- and three-point paths. Add another ordinary trace using the
short path, and separately pair selections and connected teardrops. Those
controls expose both the retention predicate and dependent-reference cleanup.
Repeated canonical cycles distinguish a stable result from transient positional
bookkeeping. These are concrete derivation procedures, not a claim every control
has been newly converted with the application.

PCB_MISSING_COMPONENT_ROUTE_IMPORT
----------------------------------

explicit member list reconciled: surviving Pad endpoints on nonempty ordinary
traces contribute each pad once, in trace and endpoint order, and establish its

claims remain errors; the importer does not guess which current object to use.

This is conditional import modernization, reported as information under

Valid explicit members remain independent of trace geometry: a net may have

endpoints, missing pad selectors alone and unrelated nets do not trigger this
reconciliation. Separate differential geometry keeps its own binding rules.
Source inspection retains the supplied syntax; normal import retains no repair
flags or obsolete endpoint/member snapshots in the editable model.

XML ordinary endpoints to absent components reach this shared repair without
attempting to translate a pad Id for a nonexistent placement. Other XML pad and
explicit member Id mappings are validated during format preparation; unresolved

A concrete external derivation starts with complete ASC/XML fixtures containing

PCB_AUTOMATIC_PAIR_MEMBERS

or nonpositive class widths/clearances use the stored routing defaults. Existing

references still require normal validation; reconstructing a table does not grant
